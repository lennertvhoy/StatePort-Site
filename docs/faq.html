What is StatePort?

StatePort keeps the goals, progress, decisions and history of AI-assisted work in readable files on your own computer, not in one chat session. An AI tool can help with the work, but it does not own your data and it does not decide what it may do.

You install it with one command, open it in your browser at an address on your own computer, and open an application: a folder of plain files with a name, a history, a check and a set of actions. The check reads your files and answers passed, not yet or invalid, with the reason. An agent action asks a model to work on a copy of the application and hands you the result as a proposal: the exact changes as a diff, and the check’s verdict before and after. You apply it, and it becomes one commit in your application, or you reject it and nothing changes.

Read why StatePort exists or how it is organized, or install it and look for yourself.

Do I need an account?

No. The whole product works without an account: opening an application, running its checks, applying a change you have reviewed, backups, and the rest of the interface.

Only two things need a model: the agent actions and the chat. For those you have two choices. You can use OpenCode’s free models, which need no account and no key; before the first request, StatePort shows you the provider’s terms and asks you to accept them. During a model’s free period, OpenCode states that data sent to that model may be used to improve it. Or you connect your own OpenCode sign-in or API key. Models and keeping up explains both.

Is it safe?

Treat it as untested software. StatePort is an early alpha and has not had an independent security review. Do not use it for important data, and try it on a computer or virtual machine where a mistake would not matter.

What the installer does to limit risk:

  • It checks your computer first. Then it downloads each file and compares it with a fingerprint (a SHA-256 checksum) before it uses the file. It also checks the release signature.
  • It asks for two confirmations, and you type each confirmation word yourself: install-packages and install-exact.
  • The address it prints is 127.0.0.1, your own computer. Do not expose it to the internet.

What it changes on your machine: it installs system packages and services inside the Ubuntu distribution you run it in, and it registers one Windows scheduled task named StatePortKeepAlive that keeps Ubuntu running so StatePort stays reachable. You can remove it again with the uninstall and purge commands in updates and removal. More detail is in security and privacy.

Where does my data live?

On your own computer, inside the Ubuntu (WSL) distribution where you installed StatePort. It is not stored in a StatePort cloud service. The installer keeps its receipts and installation records in ~/.local/state/stateport-install in that Ubuntu user’s home folder, and the local services keep your applications in the same distribution.

Because it all sits inside one distribution, removing that distribution would remove it. Keep your own backups, and read backup and recovery for what StatePort does and does not promise.

Does it need internet?

  • To install, yes. The installer downloads release files from this site and from GitHub, and downloads the container images anonymously.
  • To import a template from a public repository, yes. That is the one feature that reaches out after the install, apart from the model.
  • After install, StatePort runs as local services on your computer and you open it at a local address. Everything except agent actions and chat works with no connection.
  • Connecting an AI tool does need internet. A request to a remote provider can send task context to that provider; see before connecting an AI tool.

What can I not do yet?

  • Use anything other than Windows 11 with WSL2 and Ubuntu 24.04 on AMD64. WSL1, ARM64, macOS, native Linux, Docker Desktop, and other distributions are not supported.
  • Go back to an older release. You can move forward to a newer one, but there is no way back.
  • Import the three templates and run each of their actions. The Decision Log template is published, but importing the templates and running their actions has not been measured in this release yet.
  • Undo most changes. One undo exists: the last evidence update in the study sample.
  • Back up more than an application’s files. A backup does not include the Git history, the conversations, the index of records or the approvals, and a restore recreates files only.
  • Ask chat to do something. Chat answers questions about an application and never runs tools or changes anything.
  • Move to another computer with everything attached. The files of an application can be exported and imported; permissions, records and provider logins do not travel.
  • Use it for a team, as a hosted service, or across the public internet. It is for one person on one local computer.
  • Count on measured results for this release. The install, the restart behaviour and the resource use are not measured yet; what is measured and what is not lists the gaps.

How do I report a bug?

Open an issue on GitHub. Include the release (Alpha.26), the step you were on, and the exact message you saw. If the installer printed a refusal record: path, attach that file after checking it for anything private. Remove tokens, passwords, private URLs, and personal file contents from anything you share. Do not post secrets, and do not post details of a suspected vulnerability in public: report a suspected vulnerability privately on GitHub instead (how that works). Troubleshooting lists what helps most.

Who builds it?

StatePort is built and maintained by Lennert Van Hoyweghen. AI coding agents help write the code, under the maintainer’s direction. The source for the release is in the StatePort-Source repository. The code and the template files are AGPL-3.0-or-later, and the docs are CC-BY-4.0. The technical release files page has the release files for developers.
