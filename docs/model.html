Application and personal copy

An application is the reusable workflow and interface. Your instance is your personal copy. It contains your private state, settings, permissions, and history.

The application can ask for access, but it cannot give itself permission or take ownership of your data.

Four names, different jobs

NameWhat it meansExample
StatewareThe idea of applications whose useful state survives a model session.A learning record that remains useful after a conversation ends.
StateSpecThe contract for describing that state and its permitted operations.A template declares its files and supported actions.
ProjectState / StudyStateTemplates for particular kinds of work.Project outcomes and evidence, or study targets and reflections.
StatePortThe host that presents and manages applications and mediates their operations.Catalog, an application view, review controls, and receipts.

An instance adds your own work to a template. Two StudyState instances can begin from the same template yet have different targets, reflections, and histories. Check which instance is open before applying a change.

Saved state

Saved state is the application's current record of your goals, progress, and decisions. Screens and summaries can display that state, but they do not silently replace it.

Follow one reflection

  1. You type a reflection in the browser. At this point it is a draft.
  2. The application prepares a proposed change. You can inspect it without saving the proposed facts.
  3. You approve and apply the reviewed change. The operation records its result.
  4. The application reads the saved state and displays the reflection. Its receipt helps you inspect what happened.
  5. When you reopen the same instance, the saved reflection should still be there. A new chat session does not need to reconstruct it from memory.

If the browser loses its response between applying and showing the result, check saved state and Receipts before applying again. See the first-session guide.

Permissions

An application can use only the access you grant and the computer can safely provide. If something is missing, StatePort should stop or offer a limited mode instead of pretending the feature works.

Approvals and change records

You can allow routine work while requiring fresh approval for important actions. A change record shows what was requested, approved, changed, and checked.

Approval answers whether a particular operation may happen. Validation answers whether named checks passed. Your verdict answers whether the result was useful and correct for your purpose. These questions can have different answers.

File ownership

StatePort tracks which files belong to the application, which belong to you, and which can be rebuilt. That distinction matters when reviewing an update; it is not a promise that this alpha offers automatic in-place updates. See the update boundary.
