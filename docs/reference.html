Glossary

Stateware

Software that keeps its important state in a durable, inspectable form instead of depending on one AI session or provider.

StateSpec

The file format and rules StatePort uses for durable facts, ownership, requested access, lifecycle steps, and checks.

Canonical state

The place an application treats as the current version of a specific fact.

Instance

Your particular copy of an application, with its own private state, permissions, and history.

Change record

A record of what was requested, approved, changed, and checked.

Template

The reusable definition of an application: its starting files, rules, and supported operations. Importing creates a managed instance; it does not turn the source repository into your live application.

Proposal

A specific suggested change that you can inspect before applying. Requesting a change, approving it, and saving its result are separate steps.

Readiness

Whether the current application has the tools, services, and access required for an operation. A visible web page does not mean its AI execution path is ready.

Capability

A kind of operation an application requests and the host may permit. A request for access is not a grant, and a grant does not remove the need for an approval where one is required.

Validation

A named check against specific requirements. Passing the check supports that claim; it does not decide whether the result meets your needs.

Acceptance

Your verdict that the result meets the intended outcome. A receipt or passing test does not provide that verdict on your behalf.

Source revision

The exact Git commit used to identify imported template content. A branch name can move, while a commit identifies a particular snapshot.

Frequently asked questions

Where can I check availability?

Use the release status page.

Is a conversation the application’s truth?

No. A conversation can help with work, but important facts need a clear place to live.

Does portability mean identical behavior everywhere?

No. It means your application data and history can survive while each tool reports what it can and cannot do.

Does a change record prove a decision was good?

No. It makes the decision and result easier to inspect. You still need to judge whether the choice was right.

Where should I begin?

Start with your first session for the user workflow, or install and open for the supported environment and release status. Use troubleshooting if a step has already stopped.

Is the StudyState sample the same as my imported StudyState?

No. The sample is a small worked example. An imported repository has its own source identity, contract, content, and available controls. Follow the import guide and inspect the resulting application.

Does asking in conversation save a change?

Do not assume it does. Look for the proposal, its applied result, and the updated state. The review guide explains the distinction.

Why is an action unavailable?

The template may not declare it, your session may lack access, or a required service may be unavailable. Read the stated reason; changing models or resubmitting the same request is not a general fix. See AI tools and readiness.

Does Undo reverse everything?

No. An available Undo action has a defined local scope. It cannot automatically reverse an external effect such as a message or network request. Inspect what will change before approving it.

Can I use ProjectState after development?

Yes. A ProjectState instance can track ongoing operations as well as development. Define the operating outcome and checks explicitly; this is a use of the template, not a separate UI mode. Read the ProjectState guide.
