Security and privacy

StatePort has not had an independent security review, and it does not remove every risk. This page lists the main ones.

Main risks

AI-assisted apps can read malicious content, follow unsafe instructions, use old permissions, expose secrets or change the wrong files. A compromised computer can also get around an app’s own controls.

What StatePort tries to do about them

  • Check where software and app files came from.
  • State which files an app may change.
  • Ask before important or destructive actions.
  • Limit what AI tools and containers can reach.
  • Keep passwords and provider credentials out of app files and images.
  • Record changes and their checks so you can review them later.

Privacy

The installer downloads release files and container images from the internet. After that, StatePort runs as local services and prints an address on your own computer (127.0.0.1), which other devices cannot reach. Whether every feature works without a connection has not been measured.

App data stays on your machine by default. The plan is to send an AI model only the context the current task needs. On Alpha.20 the chat assistant was given the recent conversation, not your app state. On Alpha.21 the context it is given could not be checked, because no AI provider was connected in testing. Either way, a remote provider sees whatever is sent to it, including the conversation. Private notes, conversations, identifiers, file paths and credentials should not become analytics data.

Before connecting an AI tool

A local web interface does not make a remote AI provider local. A provider request may send task context to that provider. Before you send sensitive content, check the selected tool and model, what the request contains, and your provider account settings. AI tools and readiness has the connection steps.

Keep provider login credentials apart from app content. Do not paste access tokens into a reflection, project evidence, a public issue or a repository file. Disconnecting StatePort stops its running work. It does not erase data already sent to a provider, and it does not replace that provider’s account controls.

Sharing diagnostics

  • Start with the release version, the visible error and the action that triggered it.
  • Look through receipts, logs, diffs and screenshots before you share them. They may include prompts, paths, repository names or personal content.
  • Share the smallest excerpt that helps, and remove credentials and private data. Keep the original private.

A backup is also a copy of private app data. Verification checks integrity. It is not encryption. Keep backups protected and choose your own retention policy. See backup and recovery.

Current limits

The installer uses sudo. It installs system packages and services in the Ubuntu distribution you run it in and registers one Windows scheduled task, so use a distribution or virtual machine you can afford to lose. There is no supported one-command uninstall yet; see updates and removal.

StatePort has no security certification and no penetration test. It makes no claim of GDPR, NIS2 or other legal compliance. Review your own setup, data, providers and retention rules before you use it.

Reporting a security issue

There is no dedicated vulnerability-reporting address yet. For now, you can open a public issue for non-sensitive reports. Do not post secrets or private security details.
