Main risks

AI-assisted applications can read malicious content, follow unsafe instructions, use old permissions, expose secrets or change the wrong files. A compromised computer can also get around an application’s own controls. StatePort reduces these risks; it does not remove them.

What leaves your machine, and when

StatePort runs as local services and prints an address on your own computer (127.0.0.1). Other devices cannot reach it, and you should not expose it to the internet.

Four things can leave your machine, and only four:

  • During the install. The installer downloads the release files and the container images from this site and from GitHub, and checks each one against a fingerprint before using it. It also runs apt-get update and installs a few ordinary Ubuntu packages, for example python3-venv, fuse3 and nftables, from the package mirrors your Ubuntu is set up to use. The container runtime packages come from a signed bundle on this site, not from those mirrors.
  • When you import a template from a public repository. StatePort reads the repository you name. It does not send anything else, and it does not run the code of that repository while inspecting it.
  • When you ask a model to do something. An agent action or a chat message sends the work to the model provider you chose. A chat message also carries the files StatePort read for it: the files that the template says a model may read, at most 12 KiB, together with your pending approvals and the recent import or run records. Apart from the next item, that is the only time your content is sent to someone else.
  • A daily pass, after you accept the free-model terms. A few seconds after StatePort’s service starts, and then once a day, StatePort refreshes OpenCode’s list of free models (it contacts models.opencode.ai) and sends each model it currently uses, or is about to switch to, one short test prompt (it contacts opencode.ai), to see whether the model still answers. The test prompt is fixed text and carries none of your content. If you have switched on Keep up automatically and there is work to do, the pass can also run StatePort’s own practice tasks on up to three models, at most once a day; those tasks send StatePort’s own sample files, never your work. Until you accept the terms, StatePort does not run this pass by itself. The Models page also has a Check the model list button that refreshes the list by hand.

Everything else stays where it is. Your applications, their files, their history, your backups and the record of what happened all stay inside the Ubuntu distribution where you installed StatePort. Check actions, applying a change you have reviewed, and the whole interface work without a model and without a network.

The sandbox

When a model works on an application, it does not work on your machine. It works in a sandbox, and the sandbox is built so that a confused or malicious model has very little to reach:

  • It sees a copy of the one application it was asked to work on, and nothing else. Not your other applications, not the rest of your files, not the conversations of other applications.
  • It sees the system files it needs to run (the read-only system libraries, the CA bundle and the pinned programs) as read-only.
  • It gets a clean environment, its own working folder and its own process group, and it cannot start processes that outlive it.
  • It has a wall-clock limit and a limit on how much it can write. When the limit is reached, it is stopped.
  • It cannot reach the loopback address of the StatePort services themselves, so it cannot ask them to do anything.

Only one file can be given to it on purpose: when the chat uses your own account (an adopted OpenCode sign-in or a stored API key), the single credential file that account needs is copied into the run’s own home folder. Agent actions are never given a credential file. The agent can read that file, and the address list below bounds where it could send it. The copy is deleted with the run, and the record of the run states that this route exposes the credential to the model.

StatePort itself computes the difference between the copy and your application, so the proposal you review is the real change, not a summary from the model. A proposal that touches a file outside the application is refused before you see it.

The list of addresses a model may reach

The sandbox has no network of its own. A small forwarder inside it relays to one socket, and behind that socket StatePort acts as a gatekeeper:

  • Only the addresses on the route’s list are allowed, and only on port 443. For the free models, that list is the model provider’s addresses and whatever else the program needs to reach, measured rather than guessed.
  • Everything else is refused, and the refusal is written down.
  • The names are looked up outside the sandbox, at the gate, so the sandbox cannot ask a name server of its own.

Each run records which addresses were asked for, how many bytes went each way, and which requests were allowed or refused. You can read that in the record of the run.

Privacy

Your applications stay on your machine. What you send to a model provider is what that provider receives, including the conversation. Private notes, conversations, identifiers, file paths and credentials should not become data you send.

Using free models

You do not need an account to use StatePort. The free route needs no sign-in and no key, which is why it is offered with its terms in front of you:

  • Before the first request, StatePort shows you the provider’s terms and asks you to accept them. During a model’s free period, OpenCode states that data sent to that model may be used to improve that model. Read that text before you accept; the page links to the provider’s own wording.
  • If you decline, no free-model request is made. The rest of StatePort keeps working, and the chat can use your own account or API key instead. Agent actions use only the free models in this release.
  • With the free route, the model receives the task you asked for and the files of the copy it works on. It does not receive your other applications, and it does not receive your account details.
  • You can withdraw the consent at any time. The route then stops being used.

Models and keeping up has the full picture, including how StatePort measures models on its own practice tasks without ever using your data.

An OpenCode sign-in already on your computer

At the end of an install, the installer looks in the account that ran it for ~/.local/share/opencode/auth.json, the file where OpenCode keeps its sign-ins. It checks that the file is there without opening it. If it is, the installer uses sudo to copy the records of OpenCode Go and OpenCode, and only those, into StatePort’s private provider folders under /var/lib/stateport-control and /var/lib/stateport-exec. Records for any other provider are never copied. The original file is not changed, and nothing is sent anywhere. If there is no file, or no OpenCode record in it, nothing is copied. The line that starts with OpenCode sign-in: near the end of the install says which of these happened. The one-line command has no option to skip the copy.

  • In the web interface, only the chat can use the copy, and only for an OpenCode or OpenCode Go model. Agent actions never use it.
  • If the copied sign-in is an OAuth one, OpenCode replaces its refresh token whenever it refreshes it, so a refresh inside StatePort can sign your original OpenCode out. A sign-in that is an API key, such as OpenCode Go, does not have that problem.
  • uninstall and purge both leave the copies in place. The installer says so, and StatePort’s cleanup neither reads nor deletes these files.
  • Remove adopted sign-in on the Coding provider page deletes StatePort’s copy in its provider folder and never touches the original. The two copies in the agent-provider folders stay until you remove them yourself as an administrator, or remove the whole Ubuntu distribution.

Before connecting an AI tool

A local web interface does not make a remote AI provider local. A provider request may send task context to that provider. Before you send sensitive content, check the selected route, what the request contains, and your provider account settings.

Keep provider login credentials apart from application content. Do not paste access tokens into a reflection, project evidence, a public issue or a repository file. Disconnecting StatePort stops its running work. It does not erase data already sent to a provider, and it does not replace that provider’s account controls.

Sharing diagnostics

  • Start with the release version, the visible error and the action that triggered it.
  • Look through records, logs, diffs and screenshots before you share them. They may include prompts, paths, repository names or personal content.
  • Share the smallest excerpt that helps, and remove credentials and private data. Keep the original private.

A backup is also a copy of private application data. The check on a backup tests its integrity. It is not encryption. Keep backups protected and choose your own retention rules. See backup and recovery.

Current limits

The installer uses sudo. It installs system packages and services in the Ubuntu distribution you run it in and registers one Windows scheduled task, so use a distribution or virtual machine you can afford to lose. You can remove it again with the commands in updates and removal.

StatePort has no security certification and no penetration test. It makes no claim of GDPR, NIS2 or other legal compliance. Review your own setup, data, providers and retention rules before you use it.

Report a vulnerability

To report a suspected vulnerability in StatePort or in this site, report it privately on GitHub (opens in a new tab). This uses GitHub private vulnerability reporting, which is enabled on the public source repository; only you and the maintainer can see the report. You need a GitHub account. StatePort is an early alpha, so no response time is promised.

For ordinary bugs and feedback that contain nothing sensitive, open a public issue instead. Do not post secrets or details of a suspected vulnerability in a public issue.
