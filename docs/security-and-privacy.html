Main risks

AI-assisted applications can read malicious content, follow unsafe instructions, use old permissions, expose secrets, or change the wrong files. A compromised computer can also bypass application-level controls.

How the design reduces risk

  • Check where software and application files came from.
  • Define which files an application may change.
  • Ask before important or destructive actions.
  • Limit what AI tools and containers can access.
  • Keep passwords and provider credentials out of application files and images.
  • Record changes and their checks for later review.

Privacy

Application data stays on your machine by default. StatePort should send an AI model only the context needed for the current task. Private notes, conversations, identifiers, file paths, and credentials should not become analytics data.

Before connecting an AI tool

A local web interface does not make a remote AI provider local. A provider request may send task context to that provider. Check the selected tool and model, the information in the request, and your provider account settings before sending sensitive content. Read AI setup and readiness for the connection steps.

Keep provider login credentials separate from application content. Do not paste access tokens into a reflection, project evidence, a public issue, or a repository file. Disconnecting StatePort stops its active processing; it does not erase data already sent to a provider or replace that provider's account controls.

Sharing diagnostics

  • Start with the release version, the visible error, and the action that triggered it.
  • Review receipts, logs, diffs, and screenshots before sharing: they may include prompts, paths, repository names, or personal content.
  • Share the smallest relevant excerpt and remove credentials and private data. Keep the original private record for your own investigation.

A backup is also a copy of private application data. Verification is an integrity check, not encryption. Keep backups protected and choose your own retention policy; follow backup and recovery.

Current limits

StatePort has no security certification or penetration test. It does not claim GDPR, NIS2, or other legal compliance. Review the real setup, data, providers, and retention rules before using it.

Reporting a security issue

There is no dedicated vulnerability-reporting address yet. For now, you can open a public issue for non-sensitive reports. Do not post secrets or private security details.
