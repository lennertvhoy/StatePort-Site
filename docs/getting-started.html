Documentation / Getting started

Install StatePort on Windows 11 with WSL2.

One path, in order: get WSL2 and Ubuntu 24.04 ready, check your setup, run the one-line installer, and open StatePort in your browser. The installer asks for your password and for two typed confirmations, then prints the address to open.

Not sure what StatePort is? Read the short answer or follow one study example first.

Early alpha. This page describes Alpha.26. Alpha.24 was the previous public release. Do not use StatePort for important data. One setup is supported: Windows 11 with WSL2 and Ubuntu 24.04 on an AMD64 computer. See what is measured and what is not.

Before you start. The installer adds system packages and services inside the Ubuntu distribution you run it in, and it registers one scheduled task in Windows. You can remove it again with the uninstall and purge commands in updates and removal. If you are unsure, try it in a virtual machine.

What you need

  • A Windows 11 computer with an AMD64 (x86-64) processor. The installer refuses Windows builds older than 22000, the first Windows 11 build.
  • WSL2 (Windows Subsystem for Linux, version 2) with stock Ubuntu 24.04.
  • systemd running inside that Ubuntu. Step 1 shows how to check.
  • A normal Ubuntu user account that can use sudo. Do not run the installer as root.
  • An internet connection during the install. The installer downloads its files and the container images.
  • Windows interoperability, which WSL turns on by default, so Ubuntu can run powershell.exe.

Nothing else is supported. WSL1, ARM64, macOS, native Linux, Docker Desktop, Windows 10, and other Linux distributions are refused or untested. See platform support.

Step 1. Set up WSL2 and Ubuntu 24.04

These are standard WSL steps from Microsoft, not StatePort commands. Skip any step you have already done. Microsoft documents them in How to install Linux on Windows with WSL and Use systemd to manage Linux services with WSL.

Install WSL2 and Ubuntu 24.04

Open PowerShell as administrator (right-click it and choose Run as administrator) and run:

wsl --install -d Ubuntu-24.04

Restart Windows if it asks you to. Then open Ubuntu 24.04 from the Start menu. The first time, it asks you to create a user name and password. That is the normal Ubuntu user you will run the installer as. To confirm it runs as WSL2, run this in PowerShell and look for 2 in the VERSION column:

wsl -l -v

If it says 1, run wsl --set-version Ubuntu-24.04 2 in PowerShell.

Make sure systemd is on

Inside Ubuntu, run:

ps -p 1 -o comm=

If it prints systemd, skip to Step 2. If not, edit the WSL settings file. Microsoft's documentation says current Ubuntu images installed by wsl --install have this on already, but check anyway.

sudo nano /etc/wsl.conf

Add these two lines. If the file already has content, keep it, and add the line under an existing [boot] section if there is one:

[boot]
systemd=true

Save and leave the editor (in nano: Ctrl+O, Enter, Ctrl+X). Then, in PowerShell, run the following, and open Ubuntu again. This stops every running WSL distribution, so save your work in all of them first.

wsl --shutdown

Step 2. Check your setup

Inside Ubuntu, run these five commands. They are the same things the installer checks first.

uname -r
uname -m
grep '^VERSION_ID=' /etc/os-release
ps -p 1 -o comm=
id -u
  • uname -r prints text that contains microsoft and WSL2.
  • uname -m prints x86_64.
  • The third command prints VERSION_ID="24.04".
  • ps -p 1 -o comm= prints systemd.
  • id -u prints a number other than 0.

The installer also checks the Windows build and that Ubuntu can run powershell.exe. If a check fails, the message is explained in troubleshooting.

Step 3. Try it without installing

This is the same command as the real install, with one extra option. It checks your computer, downloads the list of container images with their fingerprints, checks those fingerprints, and installs nothing. It does not ask for sudo.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh) --transport-probe

When it works, the last line says the transport probe passed and that the installer was not executed. If it stops instead, its message names the problem; look it up in troubleshooting before you go on.

There is a second, optional dry run. It checks that the installer's helper can be fetched and verified and that its files would be created in a safe order, and it changes no packages or system files. Add --materialization-preflight in place of --transport-probe. It is not needed for a normal install.

You can compare the installer script with its SHA-256 fingerprint on the download page before you run anything.

Step 4. Run the install

Run this as your normal Ubuntu user, in an interactive Ubuntu window:

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

You can run it in any folder, including your home folder. On Alpha.24 you had to change into /tmp first, because the installer could not enter your home folder from its own service account. That is fixed now, and the extra step is gone.

What you will see, in order:

  1. The host checks from Step 2.
  2. Downloads. Each file is checked against a fingerprint built into the installer, and the release signature is checked.
  3. Ubuntu asks for your password because the installer uses sudo to install system packages. The installer prints a plan of the packages.
  4. It asks you to type install-packages to authorize that exact package plan. Type it exactly.
  5. Packages are installed and the installer prepares the rest. It prints the exact install plan and asks you to type install-exact. Type it exactly.
  6. Services are installed and started, and their health is checked.
  7. It prints the address to open and the commands you use to manage StatePort afterwards.

Let it finish and keep the window open; an interrupted run can leave files behind (see troubleshooting). Lines that start with StatePort download retry or StatePort apt update retry mean the installer is retrying a step by itself. A line saying StatePort held packages is normal: the installer pins the exact packages it installed so that ordinary updates do not change them.

On the reference test machine (a local Windows 11 virtual machine) this release took 466 seconds (about 8 minutes) once. Allow more time on a slower computer or a slower connection.

What success looks like

Near the end you see this, with your own port and your own paths:

StatePort is installed and healthy.
  OpenCode sign-in: none found on this account; nothing was copied.

  Open StatePort at: http://127.0.0.1:<port>/
    On Windows, open that same address in your normal Windows browser;
    WSL forwards localhost, so it is the same localhost address there.
    The first screen is Applications: click "Open the study sample" to start.
  install receipt: /home/<you>/.local/state/stateport-install/receipts/<receipt file>
  Your data and install records live under: /home/<you>/.local/state/stateport-install

  Commands for this installation (type them in this Ubuntu terminal):
    Open StatePort:  /home/<you>/.local/state/stateport-install/bin/stateport open
    Status:          /home/<you>/.local/state/stateport-install/bin/stateport status
    Uninstall:       /home/<you>/.local/state/stateport-install/bin/stateport uninstall    (stops and removes StatePort; your data is kept)
    Reinstall:       STATEPORT_REINSTALL=1 bash <(curl -fsSL <address of this release>/bootstrap.sh)    (your data is kept)
    Upgrade:         bash <(curl -fsSL <address of the install script>)    (installs a newer published release; your data is kept)
    Purge:           /home/<you>/.local/state/stateport-install/bin/stateport purge    (DELETES all StatePort data; asks you to type purge)

The port is chosen by the installer and can differ between computers. Use the address your installer printed. Your own home folder, receipt file and release addresses appear where this example has placeholders, and the commands are printed with their full paths. The line that starts with OpenCode sign-in: says whether the installer copied an existing OpenCode sign-in; security and privacy explains what that means. You may also see lines that start with notice:; on a successful install they were informational. The closing lines say where your data and install records live and give the exact commands to open, check, remove, reinstall, upgrade or purge StatePort. You may also see Note: this machine is not one of the tested setups; it has every capability StatePort needs, so the install continues. That is a note, not a refusal (see troubleshooting).

The install receipt is a file that records what was installed. The address is stored in it too, in a field called localUrl, if you lose the printed line. Receipts live in ~/.local/state/stateport-install/receipts/.

Step 5. Open StatePort

Open the printed address in a web browser on the same computer. Use http, not https. The address 127.0.0.1 means this computer only: nobody else on your network can open it, and you should not expose it to the internet.

You can also let the product open it for you:

~/.local/state/stateport-install/bin/stateport open

The first screen is the Applications page. While you have no applications it shows three steps: choose an AI route, create your first application, and run its first action. The first step is optional, because the study sample and every check work without an AI model; Step 6 explains it. For the second step you can choose Open the study sample, Import a template or Browse catalog. Templates explains the difference.

If the page does not load, see troubleshooting.

Step 6. Choose an AI route

StatePort can ask an AI model to do work for you, but only if a model is available. The first step on the first screen offers two routes:

  • Use free models (no account). These are OpenCode's free models. You do not need an account and you do not need a key. Before the first request, the product shows you the provider's terms and asks you to accept them. During a model's free period, OpenCode states that data sent to that model may be used to improve it. Read the terms before you accept. The agent actions use this route in this release.
  • Connect your own OpenCode sign-in or API key. You connect an account you already have. In this release only the chat uses it. The agent actions, and the practice runs on the Models page, use only the free models, so they stay off until you accept the free-model terms. What that provider does with your data is covered by your own agreement with them.

You can also skip both for now. Without an AI route everything still works except the AI actions and the chat. The check actions, the applications, the backup and the rest of the interface do not need a model.

Models and keeping up explains how StatePort chooses a model, how it measures them, and how to pin one.

What to try first

  1. Open the bundled study sample and follow your first session. It is a small study-plan app you can run in a few minutes.
  2. Read templates to see how ProjectState (a project tracker), StudyState (a study plan) and Decision Log (a decision log) are brought in.
  3. Read design a small app that keeps its state. It is a thinking exercise with nothing to install, and it explains the ideas behind what you just installed.

If a screen differs from a guide, please report it. This is an early release and screens change.

Keeping StatePort running

  • Closing Ubuntu windows. The installer registers a Windows scheduled task named StatePortKeepAlive. The task is designed to keep Ubuntu running, so that StatePort stays reachable after you close the last Ubuntu window, and to start Ubuntu again at Windows start-up (where Windows allows it), at sign-in and every 10 minutes. Windows may allow only a smaller version for your account, for example sign-in only, and the installer says so at the end when that is the case. After a full WSL shutdown on the test virtual machine, the task started Ubuntu again on its own after 68 seconds, and StatePort answered with its data intact.
  • Restarting Windows. What happens after a restart has not been measured yet on this release. If the address does not answer after a restart, sign in to Windows, open an Ubuntu window, and try again after a few minutes.
  • The port. The installer picks the port, and it can differ between installs and computers. Always use the address printed at the end of your install, or ask for it later with stateport url.

If something stops

A message that begins StatePort install: comes from the installer script. A message that begins install refused comes from the installer's own checks and writes a refusal record file you can attach to a report. Troubleshooting lists each message, its cause, and what to do. If you have tried to install on this computer before and the run stops with image_archive_conflict, there is a specific entry for it.

To report a problem, see how to report a problem. Next: updates and removal, backup and recovery, and the FAQ.
