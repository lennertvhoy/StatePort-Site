Documentation / Getting started

Install StatePort on Windows 11 with WSL2.

One path, in order: get WSL2 and Ubuntu 24.04 ready, run a dry run that installs nothing, run the one-line installer, and open StatePort in your browser. On fresh test machines the real install took about 12 to 18 minutes.

Not sure what StatePort is? Read the short answer or follow one study example first.

Early alpha, release 0.1.0-alpha.24. Do not use it for important data. It has been tested on one setup only: Windows 11 with WSL2 and Ubuntu 24.04 on an AMD64 computer, in virtual machines; real-Windows results are pending. See what is measured and what is not.

Before you start. The installer adds system packages and services inside the Ubuntu distribution you run it in, and registers one scheduled task in Windows. There is no supported one-command uninstall in this alpha, so use a distribution or virtual machine you can afford to lose. See updates and removal.

What you need

  • A Windows 11 computer with an AMD64 (x86-64) processor. The installer refuses Windows builds older than 22000, the first Windows 11 build.
  • WSL2 (Windows Subsystem for Linux, version 2) with stock Ubuntu 24.04.
  • systemd running inside that Ubuntu. Step 1 shows how to check.
  • A normal Ubuntu user account that can use sudo. Do not run the installer as root.
  • An internet connection during the install. The installer downloads its files and the container images.
  • Windows interoperability, which WSL turns on by default, so Ubuntu can run powershell.exe.

Nothing else is supported. WSL1, ARM64, macOS, native Linux, Docker Desktop, Windows 10, and other Linux distributions are refused or untested. See platform support.

Step 1. Set up WSL2 and Ubuntu 24.04

These are standard WSL steps from Microsoft, not StatePort commands. Skip any step you have already done. Microsoft documents them in How to install Linux on Windows with WSL and Use systemd to manage Linux services with WSL.

Install WSL2 and Ubuntu 24.04

Open PowerShell as administrator (right-click it and choose Run as administrator) and run:

wsl --install -d Ubuntu-24.04

Restart Windows if it asks you to. Then open Ubuntu 24.04 from the Start menu. The first time, it asks you to create a user name and password. That is the normal Ubuntu user you will run the installer as. To confirm it runs as WSL2, run this in PowerShell and look for 2 in the VERSION column:

wsl -l -v

If it says 1, run wsl --set-version Ubuntu-24.04 2 in PowerShell.

Make sure systemd is on

Inside Ubuntu, run:

ps -p 1 -o comm=

If it prints systemd, skip to Step 2. If not, edit the WSL settings file. Microsoft's documentation says current Ubuntu images installed by wsl --install have this on already, but check anyway.

sudo nano /etc/wsl.conf

Add these two lines. If the file already has content, keep it, and add the line under an existing [boot] section if there is one:

[boot]
systemd=true

Save and leave the editor (in nano: Ctrl+O, Enter, Ctrl+X). Then, in PowerShell, run the following, and open Ubuntu again. This stops every running WSL distribution, so save your work in all of them first.

wsl --shutdown

Step 2. Check your setup

Inside Ubuntu, run these five commands. They are the same things the installer checks first.

uname -r
uname -m
grep '^VERSION_ID=' /etc/os-release
ps -p 1 -o comm=
id -u
  • uname -r prints text that contains microsoft and WSL2.
  • uname -m prints x86_64.
  • The third command prints VERSION_ID="24.04".
  • ps -p 1 -o comm= prints systemd.
  • id -u prints a number other than 0.

The installer also checks the Windows build and that Ubuntu can run powershell.exe. If a check fails, the message is explained in troubleshooting.

Step 3. Run the dry run

This is the same command as the real install, with one extra option. It checks your computer, downloads the list of container images with their fingerprints, checks those fingerprints, and installs nothing. It does not ask for sudo.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh) --transport-probe

When it works, the last line begins StatePort Alpha.24 transport probe passed and ends with installer was not executed. If it stops instead, its message names the problem; look it up in troubleshooting before going on.

There is a second, optional dry run. It checks that the installer's helper can be fetched and verified and that its files would be created in a safe order, and it changes no packages or system files. Add --materialization-preflight in place of --transport-probe. It is not needed for a normal install.

You can compare the installer script with its SHA-256 fingerprint on the download page before you run anything.

Step 4. Run the install

Run this as your normal Ubuntu user, in an interactive Ubuntu window:

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

What you will see, in order:

  1. The host checks from Step 2.
  2. Downloads. Each file is checked against a fingerprint built into the installer, and the release signature is checked.
  3. Ubuntu asks for your password because the installer uses sudo to install system packages. The installer prints a plan of the packages.
  4. It asks you to type install-packages to authorize that exact package plan. Type it exactly.
  5. Packages are installed and the installer prepares the rest. It prints the exact install plan and asks you to type install-exact. Type it exactly.
  6. Services are installed and started, and their health is checked.

Let it finish and keep the window open; an interrupted run can leave files behind that stop a later run (see troubleshooting). Lines that start with StatePort download retry or StatePort apt update retry mean the installer is retrying a step by itself. A line saying StatePort held packages is normal: the installer pins the exact packages it installed so that ordinary updates do not change them.

What success looks like

Near the end you see this, with your own port and path:

StatePort is installed and healthy.
  OpenCode sign-in: none found on this account; nothing was copied.
  Open StatePort at: http://127.0.0.1:18216/
  install receipt: /home/<you>/.local/state/stateport-install/receipts/<receipt file>.json

The port varies from install to install; 18216 was one example. Use the address your installer printed. You may also see lines that start with notice:. On successful installs they were informational, for example that the port in use differed from the one first planned. The closing lines say where your data and install records live and how to stop, remove or reinstall StatePort. The line about an OpenCode sign-in says whether the installer found one; on the Alpha.22 test machine there was none, and nothing was copied. You may also see Note: this machine is not one of the tested setups; it has every capability StatePort needs, so the install continues. That is a note, not a refusal (see troubleshooting).

The install receipt is a file that records what was installed. The address is stored in it too, in a field called localUrl, if you lose the printed line.

Step 5. Open StatePort

Open the printed address in a web browser on the same computer, for example http://127.0.0.1:18216/. Use http, not https. The address 127.0.0.1 means this computer only: nobody else on your network can open it, and you should not expose it to the internet.

The first screen opens empty, with one main button, Open the study sample. Worker execution shows as disabled and the provider as not configured, each with a short explanation. That is normal.

To open the study sample, click Open the study sample. It installs the bundled sample, records a receipt and opens it after about ten seconds. The Applications list at the left may keep saying that no applications exist until you reload the page. Then follow your first session.

What you will not get yet: chat replies, coding-agent runs, per-application workspaces and container tools, the workbench terminal and files tools, and restore from the interface. The study sample needs no provider login; everything in it is proposed by a fixed script. The full list is in current limitations.

If the page does not load, see troubleshooting.

What to try first

  1. Read Design a small app that keeps its state. It is a thinking exercise with nothing to install, and it explains the ideas behind what you just installed.
  2. Follow your first session to walk through the StudyState sample, a small study-plan app: start an activity, review the change, apply it, and open the receipt.
  3. Read templates to see how ProjectState (a project tracker) and StudyState (a study plan) are brought in.

The guides are based on the design and earlier recordings. The study sample screens have since been walked through on an installed Alpha.21, and the study sample loop has been run in the browser from start to receipt; that walk-through has not been repeated on Alpha.24. Some screens still have known problems (see current limitations). If a screen differs from a guide, please report it.

Closing WSL windows, restarts, and the port

  • Closing Ubuntu windows. The installer registers a Windows scheduled task named StatePortKeepAlive. On Alpha.24 it is registered to start at Windows start-up, at sign-in and every 10 minutes; on the test machine it had never run, so its effect was not measured. On Alpha.21 it ran only at sign-in and had not run on the test machine. On Alpha.20, before any sign-out, closing the last Ubuntu window stopped StatePort, and it came back about three minutes after Ubuntu was reopened; after an interactive Windows sign-in the keep-alive task held the environment. Troubleshooting explains what the task does.
  • Restarting Windows. A planned restart has not been measured (reboot: not measured). After one unplanned restart of the Alpha.21 test machine, with nobody signed in, StatePort stayed down until Ubuntu was started by hand, and answered again about two minutes later with its saved state intact. If the address does not answer after a restart, sign in to Windows, open an Ubuntu window, and try again after a few minutes.
  • The port. The installer picks the port, and it can differ between installs and computers. Always use the address printed at the end of your install.

If something stops

A message that begins StatePort install: comes from the installer script. A message that begins install refused comes from the installer's own checks and writes a refusal record file you can attach to a report. Troubleshooting lists each message, its cause, and what to do. If you have tried to install on this computer before and the run stops with image_archive_conflict, there is a specific entry for it.

To report a problem, see how to report a problem. Next: updates and removal, backup and recovery, and the FAQ.
