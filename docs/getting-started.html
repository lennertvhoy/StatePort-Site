Documentation / Getting started

From a fresh WSL terminal to a working application.

Check the supported environment, run one command, open the local product, and keep your first application in durable state.

Alpha.15 is an early public test. Use test data, keep your own backups, and do not expose the local services to the public internet.

1. Confirm the supported environment

Open Ubuntu 24.04 in WSL2 on a Windows 11 x86-64 laptop. Run these checks inside Ubuntu:

uname -m
grep '^VERSION_ID=' /etc/os-release
ps -p 1 -o comm=

The results must be x86_64, VERSION_ID="24.04", and systemd. Run the installer as your normal Ubuntu user, not as root. You need internet access, sudo, and several gigabytes of free WSL disk space.

If PID 1 is not systemd, create /etc/wsl.conf with the following content, run wsl --shutdown from PowerShell, and reopen Ubuntu:

[boot]
systemd=true

2. Run the one-line installer

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

The bootstrap verifies Windows, WSL, Ubuntu, signed release metadata, the exact packages, and seven digest-pinned images before installing. It shows the exact package and release plans before asking you to type install-packages and install-exact. The sudo prompt is expected.

Do not close the terminal while it installs. A successful run ends with StatePort is installed and healthy and prints the exact local URL and install-receipt path.

3. Open the complete product

Open the printed http://127.0.0.1:…/ URL in your Windows browser. The address is loopback-only: the web interface, API, worker, persistence layer, and execution host stay on your laptop.

If you misplaced the URL, rerun the same installer command. An identical run is safe and rechecks the installed release rather than creating a second installation.

4. Create an application

For a built-in reviewed sample, open Catalog, choose StudyState, review what it needs, and install an instance. To use your own ProjectState, StudyState, or StateSpec repository, follow the template import guide.

5. Know where proof and state live

The installer writes a durable receipt below ~/.local/state/stateport-install/receipts. Application state and managed template copies are kept separately from replaceable container images. Inside the product, Receipts, Activity, and application provenance show what StatePort changed and why.

If installation stops

Read the final refusal code before retrying. The installer fails before or at a recorded boundary; it does not silently continue with a partially trusted release. Check platform support for environment failures and the download page for the current candidate. If a network download was interrupted, rerun the same command.
