Understand the setup before you install.

Check current blockers and the intended WSL2 setup. The steps below explain the installation path; Alpha.16 cannot complete a fresh installation.

Alpha.16 remains published, but fresh installation is blocked by a known signature-check failure. Anonymous image downloads also fail with HTTP 401 because the release image registry packages are private. Fixing the signature check alone will not complete installation. Wait for a corrected, qualified release; repeating this installer does not repair either failure. Published files remain available for inspection.

Alpha.16 is an early public test. Use test data, keep your own backups, and do not expose the local services to the public internet.

1. Confirm the supported environment

Open Ubuntu 24.04 in WSL2 on a Windows 11 x86-64 laptop. Run these checks inside Ubuntu:

uname -m
grep '^VERSION_ID=' /etc/os-release
ps -p 1 -o comm=

The results must be x86_64, VERSION_ID="24.04", and systemd. Run the installer as your normal Ubuntu user, not as root. You need internet access, sudo, and several gigabytes of free WSL disk space.

If PID 1 is not systemd, first save any work in all WSL sessions. Edit /etc/wsl.conf with administrator privileges, preserving its existing settings. Add systemd=true under the existing [boot] section, or add that section if it is missing. Then run wsl --shutdown from PowerShell and reopen Ubuntu. Shutdown stops all running WSL distributions.

[boot]
systemd=true

2. Run the one-line installer

Historical command, currently blocked: retained for identifying the affected route; wait for a corrected release.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

The bootstrap verifies Windows, WSL, Ubuntu, signed release metadata, the exact packages, and seven digest-pinned images before installing. It shows the exact package and release plans before asking you to type install-packages and install-exact. The sudo prompt is expected.

Do not close the terminal while it installs. A successful run ends with StatePort is installed and healthy and prints the exact local URL and install-receipt path.

3. Open the complete product

Open the printed http://127.0.0.1:…/ URL in your Windows browser. The address is loopback-only: the web interface, API, worker, persistence layer, and execution host stay on your laptop.

These steps describe the intended successful flow; Alpha.16 has not passed the fresh-install journey. If you already have an installation, use its recorded URL and receipt. Do not rerun the blocked public installer to recover the address.

4. Create an application

For a built-in reviewed sample, open Catalog, choose StudyState, review what it needs, and install an instance. To use your own ProjectState, StudyState, or StateSpec repository, follow the template import guide.

5. Know where proof and state live

The installer writes a durable receipt below ~/.local/state/stateport-install/receipts. Application state and managed template copies are kept separately from replaceable container images. Inside the product, Receipts, Activity, and application provenance show what StatePort changed and why.

If installation stops

Read the final refusal code before retrying. The installer fails before or at a recorded boundary; it does not silently continue with a partially trusted release. Check platform support for environment failures and the download page for the current candidate. For Alpha.16, neither the known signature error nor an anonymous registry HTTP 401 is fixed by retrying. Preserve the error and wait for a corrected release.

Report a problem without sharing private data

Include the release version, the last error code, your Windows / WSL / Ubuntu versions, and the step that stopped. Remove access tokens, passwords, private repository URLs, and personal file contents from logs. Never attach a complete home directory or credential file.

Open a documentation or installation issue. For update, backup, and uninstall guidance, read Updates and Lifecycle and recovery.
