A session is not the application

A model session can help with current work, but it should not be the only place that holds your goals or progress. The application should remain understandable even when that session is gone.

Tools are not interchangeable

One tool may support cancellation, safe file access, or detailed usage reporting while another does not. StatePort should check those abilities instead of assuming every provider works the same way.

Provider setup and readiness

Open Set up or verify provider from Workspace readiness or Platform. StatePort reports the selected provider, executable status, model configuration, StatePort connection, login presence, bounded-request result, and unavailable billing/quota information as separate observations. Installed does not mean authenticated; authenticated does not mean a request succeeded.

The supported settings surface can select Codex or OpenCode and save a model identifier. Saving is configuration only. For Codex, open Show installed login command, paste the displayed command into the Ubuntu WSL terminal, follow the one-time browser code flow, return to StatePort, refresh status, and choose Verify bounded request. The provider keeps credentials in its private directory, outside StatePort application backups and exports. The check sends one short request without application files or conversation. OpenCode selection is recorded, but execution is not available through this path. Direct API providers and other tools are not implied by a provider selector.

Use Disconnect StatePort to stop active provider work and cancel queued requests. Reconnecting permits future requests; earlier transcript content remains. Use Refresh status when an observation is unavailable.

See platform support for computer requirements and release status for the release boundary.

What portability should preserve

  • Your application files and saved state.
  • Your goals, permissions, and history.
  • A clear record of which tool did the work.
  • An honest warning when a new tool lacks a needed feature.

Moving or recovering a workspace

Portability means the durable application and its reviewed provenance can be inspected independently of one model session. A managed template copy has its own identity, history, and import receipt; the source repository stays untouched. Keep the source at a committed revision and import it again on another supported host when you want a new managed copy. Importing the template again does not move the existing instance’s saved state, activity history, receipts, or provider login.

To preserve an existing instance, use the lifecycle recovery path described in the lifecycle guide and updates and recovery. The governed restore flow creates a different managed instance from an indexed backup and leaves the source unchanged; it is distinct from importing the template source again. This describes recovery within a supported installation, not a general cross-machine migration wizard. Keep the original machine and data until a documented migration path has been checked. For an interrupted execution workspace, use Recover application workspace when the execution host offers it. Recovery reuses the sealed profile and grant and reattaches preserved data; it does not overwrite existing or partially initialized data. A provider login is separate from application portability and may need to be re-established on the new host.
