A session is not the app

A model session can help with current work, but it should not be the only place your goals or progress live. The app should still make sense when the session is gone.

Tools are not interchangeable

One tool may support cancelling, safe file access or detailed usage reports while another does not. StatePort should check these abilities instead of assuming every provider works the same way.

Provider setup and readiness

Open Set up or verify provider from Workspace readiness or Platform. StatePort shows the selected provider, whether its program is installed, the model setting, the StatePort connection, whether a login exists, the result of a test request, and quota information when it has it. Each is a separate observation. Installed does not mean logged in. Logged in does not mean a request worked.

Alpha.20 ships with OpenCode and uses it by default. Codex is not bundled. The settings can save a model name, and saving is not logging in. StatePort does not check OpenCode’s login for you, so choose Verify bounded request to send one short test request. The provider keeps its credentials in its own private directory, outside StatePort backups and exports. The test sends no app files and no conversation. A provider selector does not mean direct API providers or other tools are supported.

Use Disconnect StatePort to stop active provider work and cancel queued requests. Reconnecting allows new requests. The earlier transcript stays. Use Refresh status when an observation is unavailable.

See platform support for computer requirements and release status for what you can install.

What portability is meant to preserve

This is the goal. In Alpha.20, export and import exist for the instance’s files. Grants, receipts and provider logins do not travel, and there is no migration wizard.

  • Your app files and saved state.
  • Your goals, permissions and history.
  • A record of which tool did the work.
  • A clear warning when a new tool lacks a feature you need.

Moving or recovering a workspace

A managed template copy has its own identity, history and import receipt, and the source repository stays untouched. To get a new managed copy on another supported machine, keep the source at a committed revision and import it again. Importing the template again does not move the existing instance’s saved state, activity history, receipts or provider login.

To keep an existing instance, use the recovery steps in the lifecycle guide and in updates and removal. The restore flow creates a different managed instance from an indexed backup and leaves the source unchanged. That is different from importing the template source again. This covers recovery within a supported install. It is not a general cross-machine migration wizard. Keep the original machine and data until you have checked the result. For an interrupted execution workspace, use Recover application workspace when the execution host (the run environment) offers it. Recovery reuses the workspace’s saved profile and reattaches the data that was kept. It does not overwrite data that is already there. A provider login is separate from your app and may need to be set up again on the new machine.
