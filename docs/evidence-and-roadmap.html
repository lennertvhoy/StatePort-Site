Roadmap: what works and what comes next

Alpha.24 is the current release. It installs and passes in a clean test VM (Windows 11 with WSL2 and Ubuntu 24.04); real-Windows and reboot results are pending. This page separates what has been measured from what is designed but not measured yet.

What works today: measured on Alpha.24, Alpha.23 and Alpha.21

  • A one-line installer for Windows 11, WSL2, Ubuntu 24.04 and AMD64. Alpha.24 installed on a fresh Windows 11 test virtual machine from a local copy of the signed files: all services reported healthy, the web page and the API answered, a second run of the installer changed nothing, and the API port in the manifest matched the port it answered on. The public one-line command then installed Alpha.24 on a pristine machine and exited 0 in 474 seconds (one attempt), the study sample ran end to end with its saved state kept after a service restart and a WSL restart, and importing the StudyState template from GitHub worked. The public one-line command installed Alpha.23 on a pristine Windows 11 test virtual machine and exited 0 in about 9 minutes (3 of 4 attempts on these bytes; the 4th crashed in the optional keep-alive registration, Alpha.24 carries a fix for this, which the Alpha.24 runs did not exercise because the slow case did not occur): all services reported healthy, the web page and the API answered, and a second run of the installer changed nothing. The bundled study sample ran end to end with the durable result read back, and the saved data was still there after a StatePort service restart and a full WSL distribution restart. The install plan named one API port while the started API answered on another; the printed address worked. Alpha.21 came up healthy on 2 of 3 fresh Windows 11 test installs through the one-line command, in about 12 to 18 minutes each; the third was refused by a package check that races Ubuntu’s background updates.
  • The install sets up StatePort’s local services: the web interface, the API, the worker, a storage service and an execution host, which is a sandbox that runs work.
  • Measured on Alpha.24 and Alpha.23 through the product's own interface: the study sample loop: start an activity, review, approve, reflect, receipt, with the durable result read back and the saved state kept after a StatePort service restart and a full WSL distribution restart. Measured in the browser on Alpha.21, not repeated on Alpha.24; going back from a review withdraws the proposed change.
  • Measured on Alpha.21, not repeated on Alpha.24: importing a ProjectState or StudyState template from a local Git checkout without an ownership fix, in the browser and through the API. Importing the real StudyState_Template from GitHub inside StatePort worked on Alpha.24 (the web service has its own outbound network; on Alpha.23 the containers could not resolve external host names and the import failed).
  • Measured on Alpha.21, not repeated on Alpha.24, through the API: undo of the last evidence update, export and import, a verified backup, restore as a new instance (with a destination name) and a template upgrade.
  • Measured on Alpha.21, not repeated on Alpha.24: the notifications list and the Back up now button in the interface.
  • A Windows scheduled task, StatePortKeepAlive, that the installer registers. It is meant to keep Ubuntu running after the last WSL window closes. On Alpha.24 it is registered to start at Windows start-up, at sign-in and every 10 minutes; on the test machine it had not run, so its effect was not measured (reboot: not measured).
  • Release files with signatures and fingerprints that you can inspect on the technical release files page.

Not working yet, and designed but not built

Not working yet. These were measured as not working on Alpha.21 and have not been measured again on an installed Alpha.24. Current limitations has the full list.

  • Coding-agent runs, chat replies, restore from the interface, provider actions in the interface, the workbench terminal and files tools, per-application workspaces, the standing-authority and updater pages, and the background worker, which runs no jobs.
  • Fresh state in the Learning tab without a reload, and clear error messages for refused changes.
  • Staying reachable after a Windows restart: on Alpha.21 the keep-alive task did not start after an unplanned restart. A planned restart (reboot: not measured), and uninstall and reinstall on Windows, are not measured.
  • Memory and disk use under real work. Idle use was measured and is small.

Designed, not built. Undo for most changes and rolling back the platform, a chat assistant that reads your state, saving coding-agent output into an app’s state, backups that carry Git history and receipts, and moving an instance to another machine with its grants and receipts. Current limitations has the exact wording of each.

Current priorities

  • Fix the not-working list, and measure what is left, starting with a Windows restart and uninstall.
  • Write backup, recovery and update guidance around real workflows.
  • Test the product with people who did not build it.
  • Get a security review before asking anyone to trust important data to StatePort.

Later

After the basic path works, the plan includes more apps, more platforms, stronger backup and update tools, and optional team or hosted services.
