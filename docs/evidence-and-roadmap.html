What works today: measured on Alpha.20

  • A one-line installer for Windows 11, WSL2, Ubuntu 24.04 and AMD64. It installed StatePort and reported it healthy on seven fresh Windows 11 test installs, in about 6.5 to 15 minutes each.
  • The install sets up StatePort’s local services: the web interface, the API, the worker, a storage service and an execution host, which is a sandbox that runs work.
  • The study sample loop in the browser: review, approve, apply, reflect, receipt, undo, with the saved state kept after restarts.
  • Importing a ProjectState or StudyState template from a local Git checkout, plus export and import, a verified backup, restore as a new instance and a template upgrade, through the API.
  • A Windows scheduled task, StatePortKeepAlive, that keeps Ubuntu running after the last WSL window closes, once you have signed in to Windows.
  • Release files with signatures and fingerprints that you can inspect on the technical release files page.

Not working yet, and designed but not built

Not working yet. These are built into Alpha.20, and on my installed test copies they did not work. Fixes for most of them are being built into the next release (Alpha.21); none of that is published yet. Current limitations has the full list.

  • Chat replies, coding-agent runs, per-application workspaces and container tools, the workbench terminal and files tools, restore from the interface, the standing-authority and updater pages, and notifications.
  • Surviving a Windows restart, uninstall, and reinstall.
  • Memory and disk use under real work. Idle use was measured and is small.

Designed, not built. Undo for most changes and rolling back the platform, a chat assistant that reads your state, saving coding-agent output into an app’s state, backups that carry Git history and receipts, and moving an instance to another machine with its grants and receipts. Current limitations has the exact wording of each.

Current priorities

  • Fix the not-working list, and measure what is left, starting with a Windows restart and uninstall.
  • Write backup, recovery and update guidance around real workflows.
  • Test the product with people who did not build it.
  • Get a security review before I ask anyone to trust important data to StatePort.

Later

After the basic path works, the plan includes more apps, more platforms, stronger backup and update tools, and optional team or hosted services.
