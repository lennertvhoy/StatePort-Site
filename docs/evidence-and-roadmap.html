What works today: measured on Alpha.20

  • A one-line installer for Windows 11, WSL2, Ubuntu 24.04, and AMD64. It installed StatePort and reported it healthy on a fresh Windows 11 virtual machine, five times, in about 6.5 minutes each.
  • The install sets up StatePort's local services: the web interface, API, worker, persistence service, and an isolated execution host.
  • A Windows scheduled task, StatePortKeepAlive, that keeps the Ubuntu environment running after the last WSL window closes once you have logged on to Windows interactively.
  • Signed, checksum-pinned release files that you can inspect on the technical release files page.

Not yet measured, and designed but not built

Not yet measured. These are implemented and are described in these docs. They have not been measured on an installed Alpha.20.

  • The reviewed StudyState sample loop (it passes in the project's automated tests) and governed import of ProjectState, StudyState, and portable StateSpec Git repositories.
  • Backup and recovery controls.
  • Surviving a Windows restart, uninstall, and reinstall.
  • A full walk through every screen of the interface, and efficiency on a 16 GB laptop.

Designed, not built. A general undo and platform rollback, a chat assistant that reads your state, coding-agent output promoted into application state, backups that carry Git history and receipts, and moving an instance to another machine with its grants and receipts. See current limitations for the exact wording of each.

Current priorities

  • Measure the items above, starting with Windows restart, templates, and uninstall and reinstall.
  • Expand backup, recovery, and update guidance around real user workflows.
  • Test the product with people who did not build it.
  • Review security before asking anyone to trust important data to StatePort.

Later

After the basic journey works, the roadmap includes more applications, more platforms, stronger backup and update tools, and optional team or hosted services.
