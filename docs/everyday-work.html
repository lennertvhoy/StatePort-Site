Choose an application

After you install, the home page lists your apps and recent activity. To add one, open Catalog. You can install the StudyState sample there, or choose Import a repository to bring in a Git repository that holds a ProjectState template (a project tracker), a StudyState template (a study plan) or another valid template. Catalog is a short list I reviewed. It is not a marketplace.

For an import, StatePort reads the repository without running its code. Check the detected type, branch, exact commit, working-tree status and any findings. Approve that inspection, name the app, and choose Create isolated copy, which makes a separate copy of the repository’s committed files. If the source changes after the inspection, inspect it again, because StatePort refuses an approval that no longer matches. Your source repository is not touched.

A first session with the StudyState sample

Status. I ran this loop end to end in the browser on an installed Alpha.20, including undo and coming back later with the saved state kept. A fixed script proposes the change in the sample, not an AI model.

The StudyState sample is a small loop you can try. In Catalog, choose StudyState, look at what it needs, and install it. Open it and start the suggested activity. Start activity first shows a review of the exact change, from not started to in progress. Choose Approve Start only if that is what you want.

Once the change is applied, the activity is in progress. You can pause it, pick another activity, or write a reflection. A reflection starts as a draft in your browser. Before it is saved you see its exact effect: the sample marks the activity completed and saves the reflection when you choose Approve and apply. Afterwards you should see the activity status and your reflection. The reflection is your own account. It is not independently verified learning.

Open Receipts and look at the applied change. Then reload the page and reopen the same StudyState instance. The status and the reflection should still be there, because the sample saves them in files on disk. If they are missing, stop and check the receipt and the recovery status before you try again.

A normal session follows the same steps: read the current goal or next activity, ask for one small change, review it, apply it, check the receipt. Some apps take proposals from the chat, and the optional development Workbench has its own run path. If a control is missing, that app or release does not offer it. The chat assistant sees only the recent conversation. It does not read your study or project files, and a chat message on its own does not save a change.

Check readiness before you ask

Use Workspace readiness as a list of separate checks, not one green light. It shows Local service, Execution runtime (where work runs), Worker execution, Provider (the AI tool) and Applications. A connected service does not prove that the provider is logged in or that a request will work.

Open Set up or verify provider when the provider row needs attention. It shows the selected provider, whether its program is installed, the model setting, the StatePort connection, whether a login exists, the result of the last test request, and quota information when available. Alpha.20 ships with OpenCode and uses it by default. Codex is not bundled. An operator can save a model name. Saving is not logging in. StatePort does not check OpenCode’s login for you, so choose Verify bounded request to send one short test request. It may use some of your account quota. It does not send any app conversation or files. I have not measured a real provider request on Alpha.20.

When work needs review

StatePort keeps request, review, approval, apply, validation and receipt as separate steps. A proposal is useful even if you reject it. Your approval covers only the operation you reviewed, and StatePort checks it again against the current state, permissions and budget before it runs.

Cancel asks to interrupt the selected operation. Output from a cancelled run may be incomplete, and StatePort does not resume it. Stopping a workspace keeps it for reuse, while cancelling a workload can end it. Read the confirmation text, and what it says about undoing, before you confirm.

Receipts and recovery

Open Receipts from an app or from the app overview to search past operations. A receipt says what was requested, who acted, what changed, which checks ran and what is still uncertain. It records an operation. It does not prove the result is right. Details can include a diff, the exact record, a verification status and raw JSON, and you can export them where your install offers it.

If an app’s workspace is missing or interrupted, open the execution host details (the panel for the run environment) and choose Recover application workspace if it is offered. Recovery reuses the workspace’s saved profile and access grant and reattaches the data that was kept. It does not overwrite data that is already there. If provider work is stuck, Disconnect StatePort stops the running assistant, cancels queued requests and keeps the transcript. Reconnect only after you have checked readiness.
