Design preview. Local deployment is not available through the current installer. Check the release status.

What StatePort keeps

StatePort saves the deployment plan, your approval, the result, and later status checks. That is more useful than a command with no record of why it ran.

How a deployment happens

  1. Inspect. Read the project without changing it.
  2. Plan. List the services, images, ports, storage, and generated configuration.
  3. Approve. Show you the complete plan and wait for your decision.
  4. Run and check. Start the containers with rootless Podman and wait for their health checks.
  5. Operate. Keep status, logs, and restart controls available.
  6. Remove. Stop the deployment without deleting stored data unless you approve that separately.

Each step leaves a change record. Failed or interrupted work stays visible.

What the plan refuses

The design refuses root containers, privileged access, host bind mounts, changing image tags, missing health checks, plain-text secrets, and public network exposure.

What is not supported yet

  • Upgrade and rollback between deployment versions.
  • Remote hosts over SSH, image-registry distribution, and a dedicated deployment interface.
  • Arbitrary projects. Initial support focuses on clear Python, Node, and static web projects.
  • Cloud or public-network deployment, including Azure. The current target is a single local machine.
