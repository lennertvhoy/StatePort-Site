Documentation / Updates and removal

Updates, backups, and removal in this alpha.

This release can move you forward to a newer version, reinstall itself over the same version, and remove itself. It cannot take you back to an older one. This page says what that means and what to do.

Early alpha. This page describes Alpha.26. Alpha.24 had no supported way to update, roll back or remove StatePort. This release adds an in-place upgrade and two removal commands. Do not use StatePort for important data. See what is measured and what is not.

There is no way back. You can move forward to a newer release. You cannot go back to an older one, and data saved by one release may not be usable in another.

What this release supports

  • Fresh install on the supported setup: one command, in any folder, including your home folder. Getting started has the steps.
  • Update in place: run the one-line command of a newer release over your existing install. It offers you an upgrade, you type upgrade, and your data is kept.
  • Roll back: not supported. There is no way back to an earlier release, and data saved by one release may not be usable in another.
  • Reinstall the same version: supported. Running the same one-line command again keeps your install. With STATEPORT_REINSTALL=1 in front of it, the installer reinstalls and keeps your data.
  • Remove: two commands. uninstall stops StatePort and keeps your data. purge deletes your data as well, asks you to type a confirmation, and needs your sudo password.

Check what is installed

The install receipt records what was installed. It is a JSON file in ~/.local/state/stateport-install/receipts/, and the installer printed its path when it finished. The same information is on one line of output:

~/.local/state/stateport-install/bin/stateport status

The install records belong to one installation. Do not copy them to another computer, and do not mix records from different installations.

Updating

To move to a newer release, run the one-line install command of that release:

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

The installer sees that you already have an older version and offers an upgrade in place. Read what it prints, type upgrade, and let it run. Your applications and their data are kept.

Before you do that:

  • Make a backup of each application you care about, and keep that copy somewhere else. Backup and recovery explains how.
  • Do not replace the trusted key, do not edit generated files, and do not mix files from different releases.
  • Do not run the installer of an older release against a newer installation. There is no way back, and data saved by one release may not be usable in another.
  • Check the release status and the download page for what is current.

Reinstalling the same version

Running the one-line command again over a finished install of the same version keeps the install and changes nothing. If you want it reinstalled anyway, and you want to keep your data, put this in front of the command:

STATEPORT_REINSTALL=1 bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

If an earlier attempt left files behind, the run can stop with image_archive_conflict. Troubleshooting has the workaround for that case.

Back up before anything else

Every application has its own Back up now button. A backup archives the files of that application, not its Git history, its conversations, the index of records or the approvals you gave, and a restore recreates files only. Keep your own copy of anything you care about outside the Ubuntu distribution where StatePort runs, and do not use StatePort for important data. Container images, the install receipt and the installer's records are not a backup of your application data. See backup and recovery.

Removing StatePort

Two commands remove it. Both are in the same place as the other install commands:

~/.local/state/stateport-install/bin/stateport uninstall
~/.local/state/stateport-install/bin/stateport purge
  • uninstall stops the services and removes StatePort, and keeps your data. Use this one when you want to install it again later.
  • purge also deletes your data. It asks you to type a confirmation before it does anything, and it needs your sudo password. Read what it prints before you type.

Here is what the installer puts in place, so you know what is left behind:

  • System packages in the Ubuntu distribution. The installer holds them so ordinary updates do not change them.
  • Background services that run under Ubuntu’s systemd, and the container images they use.
  • Install records in ~/.local/state/stateport-install.
  • One Windows scheduled task, StatePortKeepAlive. It lives in Windows, not in Ubuntu. If you remove StatePort, remove this task too in Windows Task Scheduler.

Two more things to know:

  • If you want everything inside Ubuntu gone, remove the whole distribution or virtual machine you installed it in. Microsoft documents how to unregister a WSL distribution. That permanently deletes everything in it, so use it only on a distribution you created for this test and never on one you use for other work.
  • Do not delete folders under ~/.local/state/stateport-install by hand, and do not run broad rm -rf commands. The only documented exception is the folder that the image_archive_conflict workaround moves aside.
