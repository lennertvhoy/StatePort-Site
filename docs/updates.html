Documentation / Updates and removal

Updates, backups, and removal in this alpha.

In Alpha.20 there is no supported in-place update, no rollback, and no supported one-command uninstall. This page says what that means and what to do instead.

Early alpha, release 0.1.0-alpha.20. Do not use it for important data. I have measured it on one setup only: Windows 11 with WSL2 and Ubuntu 24.04 on an AMD64 computer. See what is measured and what is not.

Uninstall and reinstall are not yet measured; there is no supported one-command uninstall in this alpha. Install StatePort only on a computer, Ubuntu distribution, or virtual machine you can afford to lose.

What this alpha supports

  • Fresh install on the supported setup: measured. It installed and reported healthy on a fresh Windows 11 virtual machine with WSL2 and Ubuntu 24.04, five times.
  • Update in place: no supported command.
  • Roll back: not supported. The signed release index for Alpha.20 declares that rollback is not supported.
  • Uninstall: not yet measured. No supported one-command uninstall.
  • Reinstall: not yet measured.

Check what is installed

The install receipt records what was installed. It is a JSON file in ~/.local/state/stateport-install/receipts/, and the installer printed its path when it finished. The installer also leaves a status command at the path below. We describe it as read-only, but we have not measured it on Alpha.20.

~/.local/state/stateport-install/bin/stateport-update status

Installation records are specific to one installation. Do not copy them to another computer or combine receipts from different installations.

Updating

There is no supported way to update an installed StatePort in place, and there is no safe copy-and-paste update command. Running the one-line install command again on a computer that already has StatePort is not a tested update path either; it can stop with image_archive_conflict.

When a newer release exists, its own documentation will give its instructions. Until then:

  • Do not replace the trusted key, edit the generated files, or mix files from different releases.
  • Do not run an installer or command from an older release against an Alpha.20 installation.
  • Check the release status and the download page for what is current.

Back up before anything else

The product is designed to offer backup and restore controls; see backup and recovery. They have not been measured on Alpha.20. Until they have been, keep your own copy of anything you care about outside the Ubuntu distribution where StatePort runs, and do not use StatePort for important data. Container images, the install receipt, and the installer's records are not a backup of your application data. Even when the controls work, a backup archives the instance's files, not its Git history, conversations, receipts index or approvals, and restore recreates files only.

Removing StatePort

There is no tested removal procedure. It helps to know what the installer put in place:

  • System packages in the Ubuntu distribution, which the installer holds so that ordinary updates do not change them.
  • Background services that run under Ubuntu's systemd, and the container images they use.
  • Receipts and installer records in ~/.local/state/stateport-install.
  • One Windows scheduled task, StatePortKeepAlive, which lives in Windows and not in Ubuntu.

What we can say honestly:

  • The reliable way to remove everything inside Ubuntu is to remove the whole distribution or virtual machine you installed it in. Microsoft documents how to unregister a WSL distribution. That permanently deletes everything in it, so use it only on a distribution you created for this test and never on one you use for other work.
  • The scheduled task is separate. It stays until you remove it, and you can delete it yourself in Windows Task Scheduler. How it should be removed with StatePort has not been measured.
  • Do not delete folders under ~/.local/state/stateport-install by hand as a way to clean up, and do not run broad rm -rf commands. The only documented exception is the folder that the image_archive_conflict workaround moves aside.

Reinstalling

Reinstalling on a computer that already had StatePort is not yet measured. On a fresh setup, follow getting started. If an earlier attempt left files behind, the run can stop with image_archive_conflict, and troubleshooting has a provisional workaround.

See also what has not been measured and troubleshooting.
