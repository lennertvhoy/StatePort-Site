Update, back up, or remove StatePort deliberately.

Installed identity and user data are kept separate, so checking a release, applying a successor, removing services, and deleting state remain different actions.

Alpha.16 fresh installation is blocked. The published candidate fails its predecessor signature check, and its private GHCR packages return HTTP 401 anonymously. Do not retry the installer, swap tags, or bypass verification.

Rollback is not supported for this public candidate. Alpha.15 remains immutable, but the Alpha.16 release index declares no authenticated rollback path.

Check installed identity

On an already installed host, read the durable status without downloading or changing a release:

~/.local/state/stateport-install/bin/stateport-update status

The state root is installation-specific. Do not copy it to another machine or combine receipts from different installations; the installed authority binds the state directory identity.

Apply a successor

Only use a specifically named, signed successor whose release index, source identity, target, images, and trust information agree. The updater's intended flow is check, plan, explicit authorization, then apply; each step leaves a receipt. A supported release should document the exact command. Alpha.16 has no corrected successor here, so there is no safe copy-paste update command.

The release index keeps trust-root changes separate from ordinary updates. Do not replace the pinned key, edit the compose file, or pull mutable image tags. If an update fails or its external effect is unknown, stop and inspect the recorded recovery instructions; do not infer success from a running container.

Back up before lifecycle work

Follow backup and recovery to check an archive and restore into a separate instance where those controls are available.

Back up each durable application repository and keep the archive outside the source instance, preferably on a separate device. StatePort's backup contract excludes host Git metadata, transient engine state, secret-looking files, and secret-classified metadata; an export is not encryption, retention, or full-host disaster recovery. A restore creates a new reidentified instance and refuses to overwrite an existing or foreign target.

Do not treat container images, the install receipt, or the updater store as a backup of your application data. Keep the backup receipt and archive digest together.

Uninstall and preserve receipts

The Alpha.16 installer is available at the versioned URL below. Verify its artifact digest before invoking its uninstall mode:

(
set -eu
installer=$(mktemp)
trap 'rm -f "$installer"' EXIT
curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/0.1.0-alpha.16/stateport-installer -o "$installer"
printf '%s  %s\n' b49dbcde86b99a1fa06210d0c2f625e52b82c135d5f76adcc0f903eceeb84d8d "$installer" | sha256sum -c -
python3 "$installer" --uninstall --state-root "$HOME/.local/state/stateport-install"
 )

Uninstall removes the recorded runtime units, containers, and live runtime configuration while retaining installer state and receipts. Run it only on a host with a successfully recorded installation; it is not a repair for a failed fresh install.

Purge boundary

--purge additionally removes retained installation state. Export application data and confirm the exact state root first. Purge is destructive and intentionally requires an explicit operator decision; never substitute rm -rf or delete a broader home-directory path.
