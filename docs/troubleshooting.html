Environment checks

Run these commands inside the supported Ubuntu distribution:

uname -m
grep '^VERSION_ID=' /etc/os-release
ps -p 1 -o comm=
command -v curl sudo dpkg-deb python3 sha256sum tar

Use x86_64, Ubuntu 24.04, and systemd as PID 1. A missing command, unsupported distribution, WSL1, ARM64, or a root invocation is an environment boundary. Fix the environment or wait for a supported release; do not bypass the check.

Common refusal classes

Missing predecessor signature or digest-slot error: this is Alpha.16's recorded release defect. Preserve the exact final output and stop. Do not create the missing directory, download an unpinned bundle, or weaken signature verification.

Registry HTTP 401 / manifest download failed: the Alpha.16 GHCR packages are private to anonymous users. This is a publication/visibility blocker. Do not add credentials to the public command, use a personal token, or replace an image reference with a tag.

Trust, digest, target, or signed-index mismatch: stop. These checks protect provenance. Never continue with --skip, a hand-edited index, or a different artifact.

install-packages or install-exact not accepted: the confirmation is intentionally exact. Read the plan, then enter the requested phrase only when the release is supported and the plan matches the named target.

sudo or apt lock / package failure: save the output. Do not kill another package manager or remove lock files. Retry only after the underlying package operation has completed and only for a supported release.

Product symptoms

Imported repository is not in the catalog: confirm the repository is a supported StateSpec template, inspect its exact source and lock metadata, then refresh the catalog. If registration was interrupted, check Applications and Receipts before trying again. See import checks.

An approval is stale or missing: reopen the exact plan and compare its digest, instance, and requested effect with current state. A changed plan must be reviewed again; do not approve an old link or invent a generic approval route.

Provider is not ready: inspect the selected provider and its declared capabilities, then follow provider setup and readiness. StatePort refuses a provider that cannot meet the request; do not silently substitute another provider or paste credentials into logs.

A request appears saved but no result is visible: check the activity or receipt view for the request, run, and instance identity, then use the recorded status or reconciliation action. Do not submit a new destructive request merely because the browser lost its response.

A receipt is missing or recovery says inspection required: preserve the state root and exact output, inspect the latest receipt and recovery status, and stop before deleting or replaying files. Recovery can complete an identified effect, but it refuses when target identity cannot be verified.

The printed URL is unavailable

Use the exact URL printed after a successful health check. For an existing installation, use its saved URL and receipt. If the service was running previously, confirm you reopened the same Ubuntu distribution. Do not guess a port or expose a service on a non-loopback address.

A service is unhealthy

Keep the terminal output, release identity, and receipt path. A health failure does not prove that the stack is safe to delete or that an update completed. On an existing install, inspect status with:

~/.local/state/stateport-install/bin/stateport-update status

Use the documented lifecycle operation for the recorded state. Do not change image tags, edit generated units, remove volumes, or copy another installation's state.

Recovery boundaries

Back up application repositories before uninstall or any future update. Uninstall removes recorded runtime units and containers but preserves receipts and installer state. Purge removes retained installation state and is destructive; confirm the exact state root and export data first. Rollback is undeclared for Alpha.16 and must not be simulated by swapping Alpha.15 files.

Report safely

Record the release version, environment checks, exact final refusal code, last successful step, and whether a receipt was written. Remove access tokens, passwords, private repository URLs, personal paths, file contents, and secrets from logs and screenshots. Say whether installation finished or which step stopped.

See Getting started, Updates, and Release status for the current public boundary.
