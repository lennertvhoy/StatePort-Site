Early alpha, release 0.1.0-alpha.20. Do not use it for important data. I have measured it on one setup only: Windows 11 with WSL2 and Ubuntu 24.04 on an AMD64 computer. See what is measured and what is not.

Ground rules. Do not edit the installer, skip its checks, or run it with sudo. Do not delete folders you did not create, and do not remove package-manager lock files. After you fix a cause, run the same command again. A message that begins StatePort install: comes from the installer script and stops it.

Host checks

These run first, in both the real install and the dry run, before anything is changed. The setup they check is in Step 2 of getting started.

Run this as your normal WSL user, not root.

You see the installer stop right away.

Cause. You ran it as the root account, for example after sudo -i or in a session that opened as root.

What to do. Open a normal Ubuntu window as the user you created when Ubuntu first started, and run the command without sudo. The installer asks for sudo itself when it needs it.

WSL2 is required; WSL1 and native Linux are not this release target.

You see the installer stop.

Cause. This Ubuntu is running under WSL1, or it is not running under WSL at all.

What to do. In PowerShell run wsl -l -v. If Ubuntu-24.04 shows 1 in the VERSION column, run wsl --set-version Ubuntu-24.04 2 (a standard WSL command) and try again. Native Linux and other setups are not supported.

WSL2 AMD64 is required.

You see the installer stop.

Cause. uname -m did not print x86_64, for example on an ARM64 computer.

What to do. Alpha.20 supports AMD64 only. Use a different computer.

Cannot read /etc/os-release.

You see the installer stop.

Cause. The file that names the Linux distribution is missing or unreadable, so this is not a stock Ubuntu.

What to do. Install stock Ubuntu 24.04 as in Step 1 and run the installer there.

Ubuntu 24.04 for WSL is required.

You see the installer stop.

Cause. This is another distribution or another Ubuntu version, such as 22.04.

What to do. Install Ubuntu 24.04 (wsl --install -d Ubuntu-24.04 in PowerShell) and open that one. Check it with grep '^VERSION_ID=' /etc/os-release, which must print VERSION_ID="24.04".

Enable systemd in WSL, run wsl --shutdown in PowerShell, reopen Ubuntu, then retry.

You see the installer stop.

Cause. systemd is not running as the first process in this Ubuntu, and StatePort's services need it.

What to do. Follow Make sure systemd is on: add [boot] and systemd=true to /etc/wsl.conf, run wsl --shutdown in PowerShell, reopen Ubuntu, and check that ps -p 1 -o comm= prints systemd. Then run the installer again.

Windows interoperability is required.

You see the installer stop.

Cause. Ubuntu cannot find powershell.exe. It uses it to read the Windows version. Windows interoperability may have been turned off in wsl.conf or in a WSL settings file, for example by a work policy.

What to do. In Ubuntu, command -v powershell.exe should print a path. If it prints nothing, check whether someone changed the [interop] settings (Microsoft documents them under Advanced settings configuration in WSL), restore the defaults, run wsl --shutdown in PowerShell, and reopen Ubuntu.

Cannot verify the Windows build.

You see the installer stop.

Cause. The installer asked Windows for its build number through powershell.exe and did not get a number back.

What to do. Try the command once more. If it happens again, check that powershell.exe runs from Ubuntu (see the previous entry) and report it with the output of the five checks in Step 2.

Windows 11 build 22000 or newer is required.

You see the installer stop.

Cause. This is Windows 10 or an older build. Build 22000 is the first Windows 11 build.

What to do. Alpha.20 supports Windows 11 only.

Usage: <script> [--transport-probe|--materialization-preflight]

You see the installer stop before it does anything.

Cause. You added an option or an extra word the installer does not know. Only --transport-probe and --materialization-preflight exist.

What to do. Run the command with one of those two options, or with no option for the real install.

Missing tools and temporary files

sudo is required., curl is required before privileged installation., and similar

You see one of these messages: sudo is required., curl is required before privileged installation., dpkg-deb is required before privileged installation., python3 is required before privileged installation., sha256sum is required before privileged installation., tar is required before privileged installation.. The dry runs have their own versions: curl is required for the transport probe., sha256sum is required for the transport probe., curl is required for the materialization preflight., install is required for the materialization preflight., sha256sum is required for the materialization preflight., and stat is required for the materialization preflight.

Cause. The named program is not on your path. A stock Ubuntu 24.04 has all of them, so a missing one usually means a trimmed-down or customised image.

What to do. Install it with Ubuntu's package manager: sudo apt-get update, then sudo apt-get install followed by the package name. The package for curl is curl, for dpkg-deb it is dpkg, for python3 it is python3, for sha256sum, install, and stat it is coreutils, and for tar it is tar. If sudo itself is missing, start again from stock Ubuntu 24.04.

Cannot create a private temporary directory.

You see this message, or its dry-run versions Cannot create a private probe directory. and Cannot create a private preflight directory.

Cause. The installer could not create a private working folder under /tmp, usually because the disk is full or /tmp cannot be written to.

What to do. Free disk space (df -h shows how much is left), then run the command again.

Downloads and checksums

StatePort download retry: <file> (attempt N/4)

You see this line one or more times.

Cause. A download failed and the installer is trying it again by itself, up to four attempts.

What to do. Nothing, unless the next entry follows.

Download failed after 4 attempts: <file> (<address>)

You see the installer stop after the retry lines.

Cause. Ubuntu could not fetch that file from this site or from GitHub. Common reasons are no internet connection, a VPN or proxy that blocks the address, or a temporary outage.

What to do. Check that Ubuntu can reach the internet, turn off a VPN or proxy that might block it, wait a few minutes, and run the command again.

Checksum failed: <file>

You see the installer stop.

Cause. A downloaded file does not match the checksum built into the installer. The download may have been damaged or altered on the way, for example by a network device that rewrites traffic, or the files on the site do not match the installer.

What to do. Do not bypass this check. Run the command again once. If it fails again with the same file, stop and report it with the file name shown.

Confirmations, sudo, and packages

Authenticated package plan not confirmed.

You see the installer stop after it prints the package plan and asks you to type install-packages.

Cause. What you typed was not exactly install-packages, or the installer had no interactive terminal to read your answer from. It reads the answer from the terminal itself, so it cannot be piped or run from a non-interactive script.

What to do. Run the command again in an interactive Ubuntu window, read the plan, and type install-packages exactly.

Exact install plan not confirmed.

You see the installer stop after it prints the install plan and asks you to type install-exact.

Cause. The same as the previous entry, for the second confirmation.

What to do. Run the command again and type install-exact exactly when asked.

Cannot create sealed root package staging.

You see the installer stop after the package confirmation.

Cause. sudo could not create a private staging folder under /var/tmp. Your password may have been refused, your user may not be allowed to use sudo, or the disk may be full.

What to do. Check that sudo -v accepts your password and that the disk has free space, then run the command again.

Sealed installer copy changed., Sealed Cosign copy changed., Sealed release index changed., Sealed release signature changed., Sealed trust key changed., Sealed package bundle changed.

You see one of these six messages.

Cause. After the installer copies a verified file into a root-owned staging folder, it checks the copy again. The copy no longer matched, so the file changed between the two checks. That can be a disk fault or something rewriting files.

What to do. Stop. Run the command once more. If it happens again, report it with the exact message and do not go on.

curl installation failed., skopeo installation failed., tar is required., sha256sum is required.

You see one of these messages after the package steps.

Cause. The package step did not leave that program installed. The apt output just above the message usually says why.

What to do. Read the apt lines above it. If they mention a lock, see the next entry. Otherwise fix what apt reports, then run the command again.

StatePort apt update retry after lock contention

You see this line, followed by a pause.

Cause. Another package operation, for example Ubuntu's own automatic updates, held the package manager's lock. The installer waits, retries once by itself, and continues.

What to do. Wait. Do not kill the other package manager and do not remove lock files. If the retry also fails, let the other operation finish, then run the command again.

System folder checks

Before it places its helper program under /usr/local/libexec, the installer checks each folder on the way there. It expects them to exist, not to be symbolic links, and to belong to root without being writable by anyone else.

Root-helper parent is unavailable or symlinked: <path> and its relatives

You see one of these messages, each naming a folder: Root-helper prefix must be absolute., Root-helper parent is unavailable or symlinked: <path>, Cannot inspect root-helper parent: <path>, Root-helper parent has unsafe ownership or mode: <path> (<owner:group:mode>), Root-helper directory is symlinked: <path>, Root-helper directory is unavailable or symlinked: <path>, Cannot inspect root-helper directory: <path>, Root-helper directory has unsafe ownership or mode: <path> (<owner:group:mode>), or Unknown root-helper parent action.

Cause. A system folder such as /usr/local is a symbolic link, is missing, or has different ownership or permissions than a stock Ubuntu. The owner, group, and mode it found are shown in brackets.

What to do. This is unusual on a stock Ubuntu. If you or another tool changed those folders, put them back to Ubuntu's defaults (owned by root, mode 755), or start again from a fresh Ubuntu 24.04. If you changed nothing, report the exact message. Root-helper prefix must be absolute. and Unknown root-helper parent action. should not appear in normal use; report them.

Installer refusals and a leftover from an earlier attempt

After the package steps, the installer program itself does more checks. When one of them stops the install, you see two lines:

install refused (<code>): <reason>
refusal record: /home/<you>/.local/state/stateport-install/refusals/<file>.json

The code and reason name what was refused. The refusal record is a file with the same information. Attach it when you report the problem, after checking it for anything private.

image_archive_conflict

You see this near the end of a run, after the package steps. The image name can differ.

install refused (image_archive_conflict): retained image archive differs: stateport-web.oci.tar
refusal record: ~/.local/state/stateport-install/refusals/<timestamp>-image_archive_conflict-<id>.json

Cause. An earlier run on this computer left retained image archives in ~/.local/state/stateport-install/updater/bundles/image-archives/. This run has an archive with the same name whose contents differ, for example because the earlier run was an older release or was interrupted while copying. The installer refuses to overwrite it. You would only see this if an earlier attempt left files behind; it did not occur on our installs on fresh machines.

What to do. This is a workaround for a known alpha issue. A proper fix needs a new signed release, and I am still verifying the workaround, so treat it as provisional. Close any running StatePort, then move the folder aside with this command (it moves the folder, it does not delete it):

mv ~/.local/state/stateport-install/updater/bundles/image-archives ~/.local/state/stateport-install/updater/bundles/image-archives.old

Then run the one-line install command again. If you report this, attach the refusal record. A leftover from an older release can be the cause, so say whether you tried an earlier StatePort release on the same computer.

For any other install refused code, keep the message and the refusal record, do not change files in ~/.local/state/stateport-install, and report it.

After a successful install

The page says “Service offline” after I close Ubuntu

You see the page show Service offline, or stop loading, after you closed the last Ubuntu window.

Cause. WSL stops the Linux environment shortly after the last session ends, and StatePort runs inside it. On my fresh installs the product stopped when the last Ubuntu window closed, and it came back about three minutes after I reopened Ubuntu. The installer registers a Windows scheduled task named StatePortKeepAlive to prevent this. It runs at Windows logon, so it only takes effect after an interactive Windows logon; right after the install it has not run yet.

What to do. Open an Ubuntu window and reload the address after a few minutes. To make the keep-alive task start, sign out of Windows and sign back in; that is how I activated it in my test. Windows Task Scheduler lists the task if you want to check it. If StatePort stops again after a logon, report it.

It did not come back after I restarted Windows

You see no answer from the address after a Windows restart.

Cause. Whether StatePort comes back by itself after a Windows restart has not been measured.

What to do. Sign in to Windows, open an Ubuntu window, wait a few minutes, and try again. Please report what you saw either way.

The port is not the one I expected

You see an address such as http://127.0.0.1:18012/ whose port differs from an earlier install, another computer, or an example.

Cause. The installer chooses the port, and it can differ between installs and computers. Example numbers on this site are only examples.

What to do. Use the address printed at the end of your own install. It is also stored in the install receipt (a JSON file in ~/.local/state/stateport-install/receipts/) in a field called localUrl.

The address does not load although the install said it was healthy

You see an error in the browser, or a page that never loads.

Cause. The address only works on the computer where you installed StatePort, over http. Otherwise WSL may have stopped (see the first entry in this section), or the address you typed has a different port.

What to do. Check that you typed http://, not https://, and the printed port. Open an Ubuntu window, wait a few minutes, and reload. If it still fails, report it with the release version and what you tried.

A service looks unhealthy

You see something that does not respond or reports an error after a successful install.

Cause. The cause is not known from the address alone.

What to do. Keep the terminal output and the receipt path. Do not delete containers or volumes, do not edit generated files, and do not copy another installation's state. Report it.

Template import: the checkout does not appear, or inspection is refused

You see no repositories under Catalog → Import a repository → Import from a local source folder, or Inspect stops with Git repository inspection was refused.

Cause. The checkout was placed in /var/lib/stateport/imports by your normal Ubuntu user. The service reads it as a different user, and Git refuses to work in a repository owned by someone else.

What to do. Change the owner of the checkout to the service user, once, and retry. In Ubuntu:

sudo chown -R stateport-control:stateport-control /var/lib/stateport/imports/<repository>

Then open Catalog and import again. I measured template import working after this fix.

Report a problem

Open an issue on GitHub and include:

  • the release, 0.1.0-alpha.20, and whether the dry run passed;
  • the step you were on and the exact message, copied from the terminal;
  • the output of the five checks in Step 2;
  • the refusal record, if the installer printed one, after you check it for private content.

Remove tokens, passwords, private URLs, personal paths, and file contents from anything you post. Do not post secrets or details of a suspected vulnerability in public; see reporting a security issue.

See also getting started, updates and removal, current limitations, and the release status.
