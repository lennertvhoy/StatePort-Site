1. Put a Git repository in the import folder

For a local import, place a real Git checkout, including its .git directory, below the configured source folder. The default installed folder is:

/var/lib/stateport/imports

The checkout can be ProjectState, StudyState, or another repository that declares a supported StateSpec contract. Keep the intended version committed. A ZIP extraction without Git history cannot establish the exact commit identity that review needs.

You may also enter a public HTTPS repository and its full 40-character commit in the import drawer. StatePort fetches that exact revision for inspection without requiring a sign-in, following redirects, or running repository scripts.

2. Review and create the application

  1. Open Catalog and choose Import a repository.
  2. Refresh the discovered local candidates, or enter the public HTTPS URL and exact commit.
  3. Choose Inspect. Inspection is read-only and reports source identity, template detection, commit and working-tree findings.
  4. Read the findings. If the repository changed, is dirty, or has an error finding, fix and commit it, then inspect again.
  5. Enter the application name and check the approval box for the exact inspection.
  6. For a supported template, choose Create isolated copy. For an ordinary unsupported repository, the action is Register repository and it does not invent template actions.
  7. Wait for StatePort to reread the new application and durable receipt. Then choose Open application or View installation receipt.

Approval is bound to the inspection digest. A stale approval is refused instead of silently importing a different tree. If the response becomes uncertain, close the flow and refresh Catalog before attempting another mutation.

3. What StatePort recognizes

RepositoryHow it is identifiedResult
ProjectState v6ProjectState v6 contract files, including PROJECT.md and STATE.yaml.ProjectState managed application.
StudyStateStudyState mode and template-version compatibility markers plus its committed application files.StudyState managed application.
Portable StateSpecA valid template manifest and declared actions/capabilities that pass the adapter’s checks.Generic StateSpec managed application.

ProjectState stores project outcome, current slice, rules, and evidence. StudyState stores learner profile, targets, activities, sources, sessions, reviews, and evidence. The template contract remains useful without StatePort; StatePort wraps it with a managed application and receipts.

What StatePort copies and runs

  • The source repository is inspected read-only and remains untouched.
  • The managed copy is made from the exact reviewed snapshot and gets its own application identity, provenance, and import receipt.
  • Repository code is not executed during discovery or inspection.
  • Only actions implemented by StatePort for the detected adapter are available. Declaring a capability in a repository does not grant it automatically.
  • Application actions go through the installed service’s review, approval, and receipt boundaries. A source file is never proof that an action succeeded.

If the repository does not appear

  • Confirm the checkout is below the configured source folder and is a real directory, not a symbolic link.
  • Keep its .git directory and ensure the installer user can read it.
  • Use Refresh repositories in the drawer after copying the checkout.
  • For a public source, use HTTPS and a full commit SHA; a branch name is not an exact reviewed identity.
  • If inspection reports a dirty tree or invalid contract, make the smallest repair, commit it, and inspect again.
  • If an import response is uncertain, reread Catalog, Applications, and Receipts before retrying.
