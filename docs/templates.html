Documentation / Templates

Bring your template. Keep the source untouched.

StatePort recognizes ProjectState, StudyState, and portable StateSpec repositories, then runs an exact committed snapshot in an isolated managed workspace.

Template guide

Prepare the repository Import in StatePort Recognized templates What StatePort copies Troubleshooting Install and open

Prerequisite: install Alpha.15 and open the local URL printed by the installer. The import folder is created for the Ubuntu user who ran the installer.

1. Put a Git repository in the import folder

Clone a public repository directly into StatePort's allowlisted folder:

git clone https://example.com/your/template.git /var/lib/stateport/imports/my-template

Or clone a repository that already exists in your Ubuntu home. This transfers its committed history without giving StatePort access to the original working directory:

git clone ~/Projects/my-template /var/lib/stateport/imports/my-template

Commit the version you want to use first. Uncommitted and untracked files are reported during review and are never included in a managed template copy.

2. Review and create the application

  1. Open Catalog in StatePort.
  2. Choose Import a local repository.
  3. Select the repository. StatePort reads its files and Git metadata without executing repository code.
  4. Check the detected template type, branch, exact commit, working-tree status, and inspection findings.
  5. Enter an application name, approve that exact inspection, and choose Create isolated copy.
  6. Open the application or its durable import receipt.

If the repository changes after inspection, StatePort refuses the stale approval. Inspect again so the application always binds to the commit and content you reviewed.

3. What Alpha.15 recognizes

RepositoryDetected fromManaged application
ProjectState v6PROJECT.md and STATE.yaml with projectstate-template-v6ProjectState workspace
StudyStateStudyState's committed application and state contractStudyState workspace
Portable StateSpecA valid StateSpec template manifest and declared trusted actionsGeneric StateSpec workspace

An ordinary Git repository without a supported template contract can still be inspected and registered, but it does not gain template actions merely by being imported.

What StatePort copies and runs

  • The source repository remains untouched.
  • Only the exact committed tree is copied into StatePort-managed storage.
  • The managed copy receives its own identity, history, provenance, and import receipt.
  • Repository hooks and arbitrary repository commands are not run during inspection or import.
  • Only actions implemented and owned by StatePort for the detected adapter are available; a template cannot grant itself more authority.

If the repository does not appear

  • Confirm it is a Git repository below /var/lib/stateport/imports.
  • Do not use a symbolic link; import roots and repositories must be real directories.
  • Confirm the installer user can read the repository: git -C /var/lib/stateport/imports/my-template status.
  • Refresh Catalog after copying or cloning the repository.
  • If inspection reports an invalid or partial contract, fix and commit the named files, then inspect again.
