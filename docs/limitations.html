Exact status statement (for reviewers)

The block below is the exact status statement of the Alpha.24 release. It is kept word for word as it was written, because it is the last release with measured results.

StatePort 0.1.0-alpha.26 is the current public alpha. Its signed release index marks it a qualification candidate; it is not yet qualified. The index also declares rollback unsupported. On 22 October 2026, in a fresh Windows 11 test virtual machine (a KVM guest on a Linux workstation, not bare metal) with WSL2 and stock Ubuntu 24.04, reset to a clean snapshot, the versioned one-line command for these exact signed bytes installed StatePort 0.1.0-alpha.26 and exited 0 in 466 seconds; a second run over the finished install reported that it was already installed and changed nothing. The bundled study sample ran end to end. ProjectState_Template, StudyState_Template and a third template were imported by their public addresses and their check actions ran; all three survived a restart of the StatePort services and a full WSL restart, after which the Windows keep-alive task started Ubuntu again on its own after 68 seconds. In Microsoft Edge inside the virtual machine the interface's applications, catalog, approvals, runs, receipts, backup, restore as a new application, rename and settings worked through their real effects. Uninstall with the documented stateport command kept the data, an identical reinstall brought it back, and purge removed it. With StatePort idle, WSL held about 1.2 GB of Windows memory and no swap was used; the install grew the WSL disk by about 3.8 GB. After a cold power cycle of the virtual machine the keep-alive task started Ubuntu, but in both test runs the test machine's own SSH connection kept dropping afterwards, so whether StatePort came back could not be observed: Windows reboot survival is not measured on this release. Not measured on Alpha.26: agent actions and chat (OpenCode's anonymous free route had reached its usage limit from the test connection), the upgrade from Alpha.24, and resource use on office hardware.

Early alpha

StatePort is an early alpha, and this page describes Alpha.26. Alpha.24 was the previous public release, and its results are the ones measured so far. This page has three lists: what has been measured, what is not working yet, and what is designed but not built.

Read this page as a stranger would: everything on it is about the copy you can install today, on the one computer setup that is supported.

The one supported setup

  • Windows 11 (build 22000 or newer) on an AMD64 (x86-64) computer.
  • WSL2, not WSL1, with stock Ubuntu 24.04 and systemd running as the first process.
  • A normal Ubuntu user with sudo, not the root account.

WSL1, ARM64, macOS, Docker Desktop, native Linux, Windows 10 and other Linux distributions are not supported. The installer checks your setup before it changes anything and stops with a message if it does not match. See platform support.

What is measured, and what is not

This release was measured once, on a virtual machine. Alpha.26 (these exact signed bytes) was measured on 22 October 2026 in a local Windows 11 25H2 virtual machine (KVM, 6 GiB of memory, 4 cores) with WSL2 and a stock Ubuntu 24.04. It was installed with the versioned one-line command, which installs the same bytes as the public command. It is a virtual machine, not a laptop and not bare metal. Where a number belongs and there is none, nothing is shown instead of a guess. A result is written after its item once it exists, and an item with nothing after it has not been measured for this release.

What was measured for this release:

  • How long the install takes on the reference test machine. The install took 466 seconds (about 8 minutes) once.
  • The journey on a clean machine. Measured: the install; the study sample; ProjectState_Template, StudyState_Template and a third template imported by their public addresses, with their check actions run; the web interface in Microsoft Edge inside Windows (applications, catalog, approvals, runs, receipts, backup, restore as a new application, rename, settings); a service restart and a full WSL restart with data intact; uninstall, identical reinstall and purge. Not measured: agent actions and chat (OpenCode's anonymous free route had reached its usage limit from the test connection), the upgrade from Alpha.24, and Windows restart survival.
  • Whether the keep-alive task starts on its own. Measured: after a full WSL shutdown the Windows keep-alive task started Ubuntu again on its own after 68 seconds, and StatePort answered with its data intact.
  • Memory and disk use. With StatePort idle, WSL held about 1.2 GB of Windows memory (1.6 GB at the 95th percentile); while working about 1.1 to 1.8 GB. No swap was used. The install grew the WSL disk by about 3.8 GB and used about 3.2 GB of drive C:.
  • Removing StatePort on Windows with uninstall and purge, and installing again. Measured: uninstall (the documented stateport uninstall) removed StatePort and kept your data; installing again brought the same applications back; purge (stateport purge, with its typed confirmation) removed the data and records. Purge keeps a copied OpenCode sign-in (see Security and privacy).
  • Importing the three templates and running their check actions. Measured: the three templates were imported by their public HTTPS addresses (the default branch resolved to one exact commit), and their check actions ran, also after a service restart.

What is still not measured for this release:

  • What happens after a Windows restart.
  • What happens after a Windows sign-out.
  • Upgrading in place from the previous release. Not measured on this release.
  • Agent actions and chat. OpenCode's anonymous free route had reached its usage limit from the test connection, so no agent action or chat answer was measured on this release.

What earlier releases showed is in the exact status statement at the top of this page. In short: the install, the study sample, a restart of the services, a restart of the Ubuntu distribution and an import from GitHub were measured on the Alpha.24 release in a Windows 11 test virtual machine, which is a virtual machine and not a physical computer. Results on a real Windows computer are still missing, and so are results for a planned restart.

The installer itself is a script you can read. It checks that you have WSL2 (not WSL1), Ubuntu 24.04, systemd as the first process, Windows build 22000 or newer, powershell.exe reachable from Ubuntu, an x86-64 CPU, and a user that is not root. It asks for two typed confirmations. It has two options that install nothing: --transport-probe and --materialization-preflight. Getting started explains them.

Not working yet

These are the things this release does not do:

  • You cannot go back to an older release. You can move forward to a newer one, but there is no way back, and data saved by one release may not be usable in another.
  • The agent actions of the three templates were not measured in this release. The three templates were imported and their check actions ran. The Decision Log template is published, so you can import it; its four actions are described in the template guide.
  • Chat only answers questions. It reads the files that the template’s actions say a model may read, at most 12 KiB of them. It never runs tools and never changes anything. If you want a change, use an action.
  • Only one undo exists, for the last evidence update in the study sample. Most changes cannot be undone.
  • A backup holds the files of one application. It does not hold the application's Git history, its conversations, the index of records or the approvals you gave, and a restore recreates files only.
  • Nothing travels to another computer for you. The files of an application can be exported and imported. Permissions, records and provider logins do not travel, and there is no assistant that walks you through it.
  • There is no team and no service. No accounts for other people, no hosted version, no supported way to reach it over a network.
  • It runs on one setup only, as described above.

Designed, not built

These appear in the design, in the papers or in an earlier plan. They are not part of this release.

  • Undo for most changes. One undo exists, for the last evidence update in the study sample.
  • A chat assistant that reads all of your state. Chat reads only the files that the template’s actions say a model may read, at most 12 KiB.
  • Backup of history and records. A backup archives the files of an application.
  • Signed records. A record carries a checksum of its content. It is not individually signed.
  • A general background worker. The worker runs one fixed kind of job.
  • Container deployments of a project. It is a design preview and is not part of what the installer sets up.
  • Cloud deployment and managed hosting. They do not exist.
  • Shareable application packages (Agent Kits). They are an idea and do not exist yet.

Local use

  • StatePort is for one person on one local computer.
  • There is no hosted service, no team accounts and no supported way to reach it over a network.
  • The address it prints works on that computer only. Do not expose it to the internet.
  • The interface and the docs are in English only.

Security

  • StatePort has not had an independent security review or penetration test.
  • The installer uses sudo and changes the Ubuntu distribution it runs in. Use a distribution or virtual machine you can afford to lose.
  • StatePort makes no legal or regulatory compliance claims.

Applications and features

  • ProjectState, StudyState and Decision Log are early alpha. They are not finished, and nobody independent has evaluated them.
  • An imported template must be a Git repository under the import folder the installer creates, or a public repository. For a public repository you can name a branch, a tag or a commit; StatePort resolves that name once to the exact commit it points to. Only committed content is copied into your own application.
  • Each template brings its own check and its own actions. A template cannot give itself access that StatePort has not built.
  • The free models need no account. Before the first request you accept the provider’s terms, which say that during a free period the data sent to that model may be used to improve it. Models and keeping up has the details.
  • StatePort does not keep an agent working on your behalf without you. Every change a model proposes is shown to you first, and only what you apply is written. Review and control explains the permissions.
