Availability boundary The v0.1.0-alpha.3 signed artifacts are published and byte-intact, but installation is currently disabled: signed freshness evidence has expired and known installer and runtime defects require a successor release. Historical local receipts exist for Ubuntu 24.04 (validated_baseline) and Fedora 44 (compatible_unvalidated); they are not current install proof. Human acceptance remains pending. Alpha.2 is superseded and installation-disabled. The release ledger, download page, and alpha.3 erratum are the current availability authorities.

Availability

  • Alpha.3 is published and cryptographically intact, but installation is currently disabled and it is not human accepted, independently reviewed, or production qualified. Earlier local clean-install receipts for Ubuntu 24.04 and Fedora 44 are historical, not current install proof.
  • Alpha.2 is signed and published but superseded and not installable or accepted. Its web image omitted two runtime source trees and its bootstrap remains disabled.
  • The curated alpha.3 source archive is public; code and StateSpec artifacts are AGPL-3.0-or-later, and documentation is CC-BY-4.0. Canonical development Git and its history are private. The separately signed publicSnapshot Git identity is not remotely resolvable, so the archive must not be described as public Git history.
  • There is no hosted service: StatePort is not offered as a managed or cloud product.

Product shape

  • StatePort is designed as a single-user, local product. The normal local service binds to the loopback interface only; multi-user, public-network, SSO, and managed-service operation are not qualified.
  • The user interface and documentation are English-only.

Platform and execution host

  • Alpha.3 evaluates the portable target linux-amd64-rootless-podman-quadlet: Linux kernel, AMD64, cgroup v2, rootless Podman, Quadlet, systemd user services, and subordinate UID/GID mappings.
  • Ubuntu 24.04 is the validated_baseline; Fedora 44 is compatible_unvalidated. Debian and rolling distributions are not claimed.
  • In the alpha design, StudyState executes through a bundled synthetic executor. Model-backed execution requires a separately authenticated execution host and has no clean-install acceptance claim.

Security and compliance

  • No independent security review, formal audit, or penetration test has been performed.
  • Release signatures for this private candidate are not uploaded to a public transparency log; verification relies on the pinned alpha release public key and its recorded fingerprint.
  • StatePort makes no GDPR, NIS2, or other legal or compliance certification claim.
  • There is no active public support or vulnerability-reporting route yet.

Deployments and updates

  • Container deployment is local-only and limited to projects that satisfy the documented contract (plus assisted proposals for recognizable Python, Node, and static-web repositories)—not “deploy anything”.
  • Deployment governance for unrelated projects is a host-CLI capability. Browser and preview capabilities described in source are not evidence of a production-qualified installation.
  • The signed alpha.3 index describes an updater and pinned trust root; installed updater behavior remains bounded by the alpha candidate and its receipts.
  • Trust-root rotation is a manual, out-of-band operator act; a release artifact can never rotate trust by itself.
  • Uninstall, purge, backup, restore, update, and rollback behavior require a successfully installed exact candidate and corresponding receipts. Alpha.2 has none.
  • There is no Azure or other cloud deployment; infrastructure code has no production-apply claim.

Applications

  • StudyState's canonical production release remains unresolved; alpha evidence uses local or synthetic inputs, not a production-eligible application release.
  • Study activity shown in the alpha is deterministic synthetic execution for testing—not evidence of tutoring quality or a live autonomous model.

Evidence

  • Alpha.3 has a published supply-chain record and historical local install receipts for Ubuntu 24.04 and Fedora 44 bound to release-index digest sha256:3353fdb6477fcb5269169177c625205c7737b13c904de0c4f70801d7189f3f38. Those receipts predate the expiry of the signed freshness evidence and do not prove current installability.
  • Human acceptance, independent security review, and production qualification remain open; alpha.2 evidence was not transferred to alpha.3 bytes.
  • No comparative or performance claim is made; none should be inferred from walkthroughs or documentation.
