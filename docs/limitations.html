StatePort 0.1.0-alpha.20 is the current signed candidate; its installed-product rehearsal passed in an isolated simulation environment, and its public-route installation completed and came up healthy on a genuine Windows 11 host with WSL2 and stock Ubuntu 24.04. After an interactive Windows logon the installed keep-alive task held the WSL environment, and the installed product stayed reachable after the last WSL session closed on that host. Windows reboot survival and the remaining lifecycle, template, UI and efficiency checks are in progress.

StatePort is in early alpha. Do not use it for important data. Try it on a computer or virtual machine where a mistake would not matter, use test data, and keep your own backups.

Early alpha

StatePort is in early alpha. Do not use it for important data. Alpha.20 is a test release for people who want to try the idea and tell us what breaks. Sections below separate what was measured on a real setup from what is only design intent, so you can decide how much to trust each part.

The one supported setup

  • Windows 11 (build 22000 or newer) on an AMD64 (x86-64) computer.
  • WSL2, not WSL1, with stock Ubuntu 24.04 and systemd running as the first process.
  • A normal Ubuntu user with sudo, not the root account.

WSL1, ARM64, macOS, Docker Desktop, native Linux, Windows 10, and other Linux distributions are not supported. The installer checks the supported setup before it changes anything and stops with a message if it is not met. See platform support.

What works today

These are the only product claims this documentation makes about how Alpha.20 behaves on a real setup.

  • Install. The public one-line command installed Alpha.20 and reported it healthy on a fresh virtual machine running genuine Windows 11 25H2 with WSL2 and stock Ubuntu 24.04. This was repeated five times, and each install took about 6.5 minutes.
  • What a good install prints. StatePort is installed and healthy., then Open StatePort at: http://127.0.0.1:<port>/, then a path to an install receipt under ~/.local/state/stateport-install/receipts/. The port number varies, for example 18012.
  • Keeping WSL running. The installer registers a Windows scheduled task named StatePortKeepAlive, which runs at logon (interactive). After an interactive Windows logon it keeps the Ubuntu environment running after the last WSL window closes. Without it, WSL stops shortly after the last session ends, so StatePort can stop until the next Windows logon or WSL launch.

The installer itself is a script you can read, and it enforces its prerequisites: WSL2 (not WSL1), Ubuntu 24.04, systemd as the first process, Windows build 22000 or newer, powershell.exe reachable from Ubuntu, x86-64, and not running as root. It asks for two explicit confirmations, and it has two options that install nothing: --transport-probe and --materialization-preflight. Getting started explains them.

Not yet measured

  • The StudyState Sample loop on an installed Alpha.20. Start an activity, review, approve, write a reflection, open the receipt, and read the saved state again after a service restart. This is implemented and passes in the project’s automated tests. It has not yet been run end to end on an installed Alpha.20.
  • Windows restart. Whether StatePort comes back by itself after Windows restarts. Reachability after the last WSL window closes is measured (after you sign in to Windows); a Windows reboot is not.
  • Templates on the installed product. Importing a ProjectState or StudyState repository into an installed StatePort.
  • Uninstall and reinstall. Uninstall and reinstall are not yet measured; there is no supported one-command uninstall in this alpha. See updates and removal.
  • The full interface. Every screen and control has not been checked one by one on an installed Alpha.20.
  • Efficiency on a 16 GB laptop. Resource use of the installed stack has not yet been measured: memory, processor, disk, and battery use on an ordinary laptop.
  • Recovery guards. Recovery retains resources of unknown ownership. The guard has unit and local tests and a known earlier defect that was fixed, and it is not yet qualified on an installed host.

The measured installs ran on virtual machines, not on a physical laptop. A real request to an AI provider has also not been measured on Alpha.20. Something that has not been measured may work or may not; we do not know yet.

Designed, not built

These are described in the design, in these guides or in the papers. They are not features of Alpha.20.

  • General undo. One undo exists: the last StudyState Sample evidence update. Most changes have no undo. Platform rollback is not supported; the signed Alpha.20 release index declares it unsupported.
  • A chat assistant that reads your state. The chat assistant sees only the recent conversation, not your study or project state. Governed actions get a bounded context pack built from state; chat does not.
  • Coding-agent output promoted into application state. For deterministic application actions the system applies what you approve. Output from coding agents is recorded as a run result and is not promoted into application state by StatePort.
  • Backup of history and receipts. A backup archives the instance’s files, not its Git history, conversations, receipts index or approvals. Restore creates a new instance from those files; it does not reconcile interrupted work or external effects.
  • Moving an instance to another machine. Portable export and import exist for the instance’s files. Grants, receipts and provider logins do not travel, and there is no migration wizard.
  • Guided flows for imported templates. An imported ProjectState or StudyState is validated and stored as an isolated managed copy with an inspection action. The guided flows exist only in the StudyState Sample, and the StudyState next-activity engine is not surfaced in StatePort.
  • Signed receipts. Receipts carry content digests; they are not individually signed.
  • A general worker. The worker runs one fixed container job type today; agent runs and chat are tracked by the web service.

Local use

  • StatePort is designed for one person on one local computer.
  • There is no hosted service, team account system, or supported public-network setup.
  • The address it prints works on that computer only. Do not expose it to the public internet.
  • The interface and documentation are in English only.

Security

  • StatePort has not had an independent security review or penetration test.
  • The installer uses sudo and changes the Ubuntu distribution it runs in, so use a distribution or virtual machine you can afford to lose.
  • StatePort does not claim legal or regulatory certification.

Applications and features

  • StudyState and ProjectState are early-alpha templates, not finished or independently evaluated products.
  • By design, imported templates must be Git repositories under an import folder the installer creates, and only committed content is copied into the managed application. This comes from the product's design and has not been measured on an Alpha.20 install. See templates.
  • There is no supported in-place update or rollback. See updates and removal.
  • Alpha.20 ships and defaults to OpenCode as its coding agent; Codex is not bundled. Provider authentication is not verified by StatePort for OpenCode; use Verify bounded request to test one short request. A real provider request has not been measured on Alpha.20.
  • Container deployment is a design preview and is not available through the current installer. Cloud deployment and managed hosting are not available.
  • Agent Kits are a roadmap idea and are not available.
