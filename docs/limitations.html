Exact status statement (for reviewers)

StatePort 0.1.0-alpha.20 is the current signed candidate; its installed-product rehearsal passed in an isolated simulation environment, and its public-route installation completed and came up healthy on a genuine Windows 11 host with WSL2 and stock Ubuntu 24.04. After an interactive Windows logon the installed keep-alive task held the WSL environment, and the installed product stayed reachable after the last WSL session closed on that host. Windows reboot survival and the remaining lifecycle, template, UI and efficiency checks are in progress.

Early alpha

StatePort is an early alpha. Alpha.20 is a test release for people who want to try it and tell me what breaks. This page has three lists: what works today, what I have not measured yet, and what is designed but not built. Only the first list describes measured behavior.

The one supported setup

  • Windows 11 (build 22000 or newer) on an AMD64 (x86-64) computer.
  • WSL2, not WSL1, with stock Ubuntu 24.04 and systemd running as the first process.
  • A normal Ubuntu user with sudo, not the root account.

WSL1, ARM64, macOS, Docker Desktop, native Linux, Windows 10 and other Linux distributions are not supported. The installer checks your setup before it changes anything and stops with a message if it does not match. See platform support.

What works today

This is the only list that describes measured behavior of Alpha.20 on a real setup.

  • Install. The public one-line command installed Alpha.20 and reported it healthy on a fresh virtual machine with Windows 11 25H2, WSL2 and stock Ubuntu 24.04. I ran it five times. Each install took about 6.5 minutes.
  • What a good install prints. StatePort is installed and healthy., then Open StatePort at: http://127.0.0.1:<port>/, then the path to an install receipt under ~/.local/state/stateport-install/receipts/. The port number varies, for example 18012.
  • Keeping WSL running. The installer adds a Windows scheduled task called StatePortKeepAlive. It runs when you sign in to Windows and keeps Ubuntu running after you close the last WSL window. Without it, WSL stops shortly after the last session ends, and StatePort stops with it until your next sign-in or until you start WSL again.

The installer is a script you can read. It checks that you have WSL2 (not WSL1), Ubuntu 24.04, systemd as the first process, Windows build 22000 or newer, powershell.exe reachable from Ubuntu, an x86-64 CPU, and a user that is not root. It asks for two typed confirmations. It has two options that install nothing: --transport-probe and --materialization-preflight. Getting started explains them.

Not yet measured

  • The StudyState sample loop on an installed Alpha.20. Start an activity, approve it, write a reflection, open the receipt, restart the service and read the saved state again. All of this passes in the project’s automated tests. I have not yet run it end to end on an installed Alpha.20.
  • Windows restart. Whether StatePort comes back by itself after Windows restarts. After you sign in, it stayed reachable when the last WSL window closed. A reboot is a different case, and I have not measured it.
  • Templates on the installed product. Importing a ProjectState (project tracker) or StudyState (study plan) repository into an installed StatePort.
  • Uninstall and reinstall. Neither is measured, and there is no supported one-command uninstall in this alpha. See updates and removal.
  • The full interface. I have not checked every screen and control on an installed Alpha.20.
  • Speed and memory use. I have not measured how much memory, processor, disk or battery the installed stack uses on an ordinary 16 GB laptop.
  • Recovery safeguards. Recovery is meant to leave alone anything it cannot show belongs to the instance it is recovering. That check passes the project’s automated tests and local runs, and an earlier bug in it was fixed. I have not tested it on an installed system.

The measured installs ran on virtual machines, not on a physical laptop. A real request to an AI provider has not been measured on Alpha.20 either. Something I have not measured may work or may not. I do not know yet.

Designed, not built

These appear in the design, in these docs or in the papers. They are not part of Alpha.20.

  • Undo for most changes. One undo exists: the last evidence update in the StudyState sample. Most changes cannot be undone. Alpha.20 does not support rolling back the platform, and its release file says so.
  • A chat assistant that reads your state. The chat assistant sees only the recent conversation. It does not read your study or project files. Actions that go through StatePort’s approval steps get a small bundle of information built from the saved state. Chat does not.
  • Saving coding-agent output into your app’s state. For actions that follow a fixed script, such as the StudyState sample, StatePort applies what you approve. Output from coding agents is recorded as a run result. StatePort does not turn it into saved state.
  • Backup of history and receipts. A backup archives the instance’s files. It does not include Git history, conversations, the receipts index or approvals. Restore creates a new instance from those files. It does not finish interrupted work or check what happened outside StatePort.
  • Moving to another machine. Export and import work for an instance’s files. Grants, receipts and provider logins do not travel, and there is no migration wizard.
  • Guided flows for imported templates. An imported ProjectState or StudyState is checked and stored as a separate copy with one inspection action. The step-by-step flows exist only in the StudyState sample. StudyState’s next-activity engine, the part that picks what to study next, is not part of StatePort.
  • Signed receipts. Receipts carry a checksum of their content. They are not individually signed.
  • A general background worker. The worker runs one fixed kind of container job. Agent runs and chat are tracked by the web service.

Local use

  • StatePort is for one person on one local computer.
  • There is no hosted service, no team accounts and no supported way to reach it over a network.
  • The address it prints works on that computer only. Do not expose it to the internet.
  • The interface and the docs are in English only.

Security

  • StatePort has not had an independent security review or penetration test.
  • The installer uses sudo and changes the Ubuntu distribution it runs in. Use a distribution or virtual machine you can afford to lose.
  • StatePort makes no legal or regulatory compliance claims.

Applications and features

  • StudyState (a study-plan template) and ProjectState (a project-tracking template) are early alpha. They are not finished, and nobody independent has evaluated them.
  • Imported templates must be Git repositories under an import folder the installer creates, and only committed content is copied into the managed app. That is how it is built. I have not measured it on an Alpha.20 install. See templates.
  • There is no supported in-place update or rollback. See updates and removal.
  • Alpha.20 ships and defaults to OpenCode as its coding agent. Codex is not bundled. StatePort does not check OpenCode’s login for you. The Verify bounded request button sends one short test request. A real provider request has not been measured on Alpha.20.
  • Container deployment is a design preview and is not in the Alpha.20 installer. Cloud deployment and managed hosting do not exist.
  • Agent Kits (shareable app packages) are an idea and do not exist yet.
