What StudyState is

StudyState is a template for a study plan. It keeps a learner’s profile, targets, sources, activities, sessions, reviews and evidence as readable Markdown and YAML files. You can run it through a coding agent or through StatePort. The small StudyState sample is a worked app that shows the saved loop. An imported StudyState repository is a different source: StatePort checks it and stores it as a separate copy with one inspection action. The step-by-step flows exist only in the sample.

The sample loop: choose Start on the current activity, review the change from not started to in progress, and approve it. Write a reflection as a draft in your browser, review its exact effect (it also marks the activity completed), then apply it as evidence. Open the receipt to see what StatePort recorded. Reload and reopen the same instance. The completed activity and the reflection should still be saved. A fixed script proposes the change in the sample, not an AI model.

A chat can help you learn, but chat history is not the record. The files are.

Choosing the next activity

The next-activity engine belongs to the StudyState template. StatePort does not show it. In the template’s own design, the engine can pick a question, a spaced review, a paper exercise, a lab, an outside resource, interview or presentation practice, a voice note, a diagram, or an upload-and-review task. Due reviews stay visible. For subjects that change fast, it asks for fresh source information before it asks a question.

The StudyState sample offers a fixed set of activities and one small activity-and-reflection flow. An imported StudyState does not get the engine as a StatePort screen. Look at the imported files and their own instructions.

Three modes of the template

  1. Template mode: the public copy stays generic and holds no learner data.
  2. Bootstrap mode: a new repository records where it came from while you set up your learner profile and first target.
  3. Learner mode: the repository holds your targets, evidence, sessions, reviews and next action.

Use the template’s own setup to create your instance, or make a separate learner repository. Do not put your own data in the public template. Run its sanity check script after setup and after you change state.

Reflection becomes a change you review

In the sample, the reflection starts as a draft in your browser. Before it is saved, you see its exact effect on the activity and the evidence. Apply it only if it matches what you meant to record. The saved reflection is your own account. It is not independently verified progress.

The agent may suggest a change, but the saved state only changes after you apply the reviewed action. The receipt records what StatePort observed.

Undo and change history

One undo exists today. The sample can undo its last evidence update. The undo is a reviewed change too: it restores the earlier evidence and stays tied to the original change and its receipt, so it does not erase the record of what happened. Most other changes cannot be undone, and Alpha.20 does not support rolling back the platform.

StudyState keeps a history of sessions and activities next to the current state.

If you work directly in a repository, look at the diff and the history before you repair anything. Keep the evidence that explains why you corrected it.

Saved state and restarts

After the sample loop, reload and reopen the same instance and go back to the activity. It should still be completed, with the reflection in the evidence. The project’s automated test restarts the service and reads the saved plan again. That has not been run on an installed Alpha.20. On Alpha.20, StatePort stayed reachable after the last WSL window closed (once you were signed in to Windows). A Windows reboot has not been measured.

In a repository instance, closing a session does not erase your goals, target map, review queue, source list or next action, because they are files. Back up before upgrades or big edits, and keep your learner data when you apply template improvements.

What StudyState does not do

  • It does not treat source coverage or one easy answer as proof you are ready.
  • It does not call information current without fresh source information.
  • It does not install dependencies or change system settings without your consent.
  • It does not put your data in the public template or in a public repository.
  • StatePort does not give a StudyState file free rein as an agent. The installed permissions decide what it can do.

Use StudyState

Try the sample

  1. Open the StudyState sample and choose Start on its current activity.
  2. Review the exact change, then choose Approve Start so the activity becomes in progress.
  3. Write a reflection, review its proposed effect, and choose Approve and apply to save it as evidence.
  4. Open the receipt, reload the app, and check that the activity and reflection are still there.

Import a template

Choose Import a repository and give a public exact commit or a local checkout. Check the identity, the source commit and what StatePort detected before you create the separate copy. The imported repository does not have the sample’s screens or the next-activity engine.

Use the repository directly

Clone the public template into a new learner repository, set up the profile and first target, then run its environment check, its setup helper (it asks for consent), its sanity check and its demo replay. Keep the public template separate from your learner repository.

For how to prepare a source, see Use a template. For the project tracker template, see ProjectState. For availability, see release status.
