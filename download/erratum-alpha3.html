Erratum — v0.1.0-alpha.3

Installation is currently disabled.

This erratum explains, in plain language, why the published alpha.3 release cannot be installed right now and what to do instead. It was added on 8 August 2026 without changing any signed release file.

What happened?

Two independent problems make v0.1.0-alpha.3 non-installable today:

  • The signed freshness evidence has expired. Every signed image in the release records a vulnerability scan from 6 August 2026 with a maximum accepted age of 24 hours. Current-time verification now refuses all seven images — the release fails its own freshness gate before anything is installed. Signed freshness evidence cannot be renewed without issuing a new candidate.
  • The release ships known installer and runtime defects. The committed installer does not provision or protocol-health-check the declared execution host, and goal execution in this candidate is synthetic. These are defects in the released bytes themselves, so they can only be fixed by a successor release, never by re-downloading this one.

Is the signed release corrupted?

No. The published bytes are intact: every file under the versioned release directory is unchanged since publication, the release index and its signature bundle still match their recorded SHA-256 digests, and the image set matches the signed payload. The installation failure is a time-based freshness refusal plus known defects — not tampering, corruption, or a silent replacement.

Can I install it now?

No. Do not run the old one-line install command. The installer refuses at verification time because the freshness window has closed, and even a forced install would run into the known execution-host and synthetic-execution defects.

Earlier install receipts for Ubuntu 24.04 (validated_baseline) and Fedora 44 (compatible_unvalidated) were recorded while the freshness evidence was still valid. They are historical evidence, not proof that the release is installable now. Owner acceptance, independent security review, and production qualification do not exist for this release.

What should I do next?

  • Wait for a successor release that carries fresh signed scan evidence and fixes the installer and runtime defects.
  • Watch the release status page — it is the first place a successor is announced.
  • If you already experimented with alpha.3, treat it as an inspection build, not an accepted product.
  • Questions or findings: open an issue.

What evidence remains available?

The complete signed evidence set stays online for inspection on the download page:

  • The signed release index (release-index.json, SHA-256 d02709a250369b96c7bf5c39659d9080ff53d0cf0e20d391222fe5c1b0d4ae93) and its Sigstore signature bundle, signed payload digest sha256:2639e29d6ca0a5bd83d07013edb49f22692efaf53a6049234fe6b70810c89166.
  • The pinned trust key fingerprint sha256:3dca6219e41310c6a95a8189669aacad3198e6c84489946406b8f986e1f4211a and the seven pinned Linux AMD64 image digests.
  • Supply-chain records: SBOM tool provenance, vulnerability-scan provenance, export manifest, and build-comparison records.
  • The release notes and known limitations shipped with the candidate.
  • The historical local install receipts for Ubuntu 24.04 and Fedora 44, bound to release-index digest sha256:3353fdb6477fcb5269169177c625205c7737b13c904de0c4f70801d7189f3f38 — useful history, not current installability.

Source and licensing

  • The canonical development Git repository is private. The canonical source identity recorded in the release index (commit fa4ea4b7f08e78669e194c204b59206ab109a02f, tree aec60303045e7a9c8255b941c761d904af85ec10) names that private repository; you cannot fetch it, and that is expected.
  • The release index separately records a signed publicSnapshot Git identity (commit 43d6b4491b962c963a0ecafc060e0dfc7e334dc0, tree 3bbe46db14a7c929e6f0a17ca153ec686192aa51). That identity is not remotely resolvable — no public Git repository serves that exact snapshot or its history. This is a known successor-release blocker, recorded openly rather than hidden.
  • What is publicly distributed: the curated alpha.3 source archive (stateport-source.tar, SHA-256 17f5680c30841b1e831b37df02dca8f03c2c03d265a42633dd525f99bd613398) shipped alongside the signed artifacts. The curated alpha.3 source archive is public and classifies code and StateSpec artifacts as AGPL-3.0-or-later and documentation as CC-BY-4.0. Archive availability does not make the canonical development Git history public; that repository remains private.

Bottom line. Alpha.3 remains published and cryptographically intact; installation is disabled; a successor release is required. Nothing on this page changes the signed bytes.
