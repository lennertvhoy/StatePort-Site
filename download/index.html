Install StatePort Alpha.23

One command installs StatePort on Windows 11 with WSL2 and Ubuntu 24.04. It sets up a web interface, an API, a background worker, storage and a sandbox where work runs.

Alpha.23 installs and passes in a clean test VM; real-Windows and reboot results pending. It is an early alpha with known limits, listed below.

What has and has not been tested

  • Tested: Alpha.23 installed on a fresh Windows 11 virtual machine with WSL2 and stock Ubuntu 24.04, reset to a clean snapshot, from a local copy of the signed files. All services reported healthy, the web page and the API answered, and a second run of the installer reported that StatePort was already installed and changed nothing. One measured defect stays open: the install plan and manifest named API port 18464 while the started API answered on 18447; the web address the installer printed was correct and worked. The public one-line command was not used for this install, and the install time was not recorded. On Alpha.21 the public command came up healthy on 2 of 3 fresh test installs, and the other attempt was refused with package_installation_invalid (see troubleshooting).
  • Tested on Alpha.21, not repeated on Alpha.23: the StudyState sample (a small study-plan app) in the browser: open it with one click, start an activity, review the exact change, approve, write a reflection, and open the receipt. The saved state was still there after a reload. Going back from a review withdraws the proposed change.
  • Tested on Alpha.21, not repeated on Alpha.23: importing a ProjectState and a StudyState template from a local Git checkout, in the browser and through the API, without an ownership fix. Through the API: undo of the last evidence update, export and import, a verified backup and restore as a new instance (the request needs a destination name). The notifications list and the Back up now button also worked.
  • Not working yet: on Alpha.21, coding-agent runs were refused before they started, chat replies failed because no AI provider could be connected, restore from the interface failed, provider actions in the interface were refused, the workbench terminal and files tools did not work, and per-application workspaces were unavailable. The Learning tab could show old numbers until you reloaded, and refused changes gave vague error messages. None of this has been measured again on an installed Alpha.22. The keep-alive task had not run on the test machine. A planned Windows reboot is not measured (reboot: not measured), and uninstall was not run on Windows. The full list is on current limitations.
Exact status statement (for reviewers)

StatePort 0.1.0-alpha.23 is the current signed release. It installs and passes in a clean test VM; real-Windows and reboot results pending (reboot: not measured). In a fresh Windows 11 test virtual machine with WSL2 and stock Ubuntu 24.04, reset to a clean snapshot, the Alpha.23 installer, run from a local copy of the signed files with the container images pulled from the registry, installed StatePort. All services reported healthy, the web page and the API answered, and a second run of the installer over the finished install reported that it was already installed and changed nothing. One measured defect stays open on that install: the install plan and manifest named API port 18464 while the started API actually answered on port 18447; the installer prints the address of the service that is really listening, so the printed web address worked. The installed keep-alive task was registered to start at Windows start-up, at sign-in and every 10 minutes, but it had not run on the test machine. Reboot: not measured. Uninstall was not run on Windows. The study sample in the browser, undo, export and import, backup and restore, and template import were last measured on Alpha.21 and have not been repeated on Alpha.23. On Alpha.21, coding-agent runs, chat replies, restore from the interface, the workbench terminal and files tools, per-application workspaces, and the standing-authority and updater pages did not work, and none of that has been measured on an installed Alpha.23.

Before you start

Work through these in order. Each one is a check you can run in a minute.

  1. Windows 11 on a 64-bit Intel or AMD computer, with an internet connection and several gigabytes of free disk space.
  2. WSL2 with Ubuntu 24.04. If you do not have it yet, open PowerShell and run the command below, restart if Windows asks, then open Ubuntu and create your Linux user. To confirm Ubuntu runs as WSL2, run wsl --list --verbose in PowerShell and look for 2 in the VERSION column. 
    wsl --install -d Ubuntu-24.04
  3. A normal Ubuntu user with sudo. Do not run the installer as root.
  4. systemd switched on inside Ubuntu. In Ubuntu, run the command below. It should print systemd. 
    ps -p 1 -o comm=
    If it prints anything else, open /etc/wsl.conf with sudo nano /etc/wsl.conf, keep any lines already there, and add these two lines (skip the first if a [boot] section already exists): 
    [boot]
systemd=true
    Then run wsl --shutdown in PowerShell and reopen Ubuntu. This stops every running WSL distribution, so save your work first.

Read the longer getting-started guide for the same checks in more detail.

Optional: run a dry run first

Add --transport-probe to the command. It installs nothing and does not ask for sudo: it checks your machine (WSL2, Ubuntu 24.04, systemd, Windows 11), downloads the list of container images with their fingerprints, and checks those fingerprints. If a prerequisite is missing, it stops and names it.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh) --transport-probe

A passing dry run ends with a line that starts StatePort Alpha.23 transport probe passed.

Install

Open Ubuntu 24.04 in WSL2 and run this as your normal Ubuntu user:

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

What the installer does and asks, in order:

  1. Checks your machine before changing anything, then downloads the release and checks each file against a fingerprint.
  2. Asks for your Ubuntu password (sudo) to install a few system packages.
  3. Shows the package plan and asks you to type install-packages to approve it.
  4. Shows the exact install plan and asks you to type install-exact to approve it.
  5. Installs and starts StatePort, then prints the result.

Expect it to take a while: Alpha.21 took about 12 to 18 minutes on a test virtual machine (the Alpha.22 and Alpha.23 install times were not recorded), and longer on a slow connection. If it stops with package_installation_invalid, wait a minute and run the same command again; troubleshooting explains why.

You can check the installer before you run it. Its SHA-256 fingerprint is f14c53e5ce596cd81b234f70b23d755aacc9eac9bd2adf3644a251807090d0c8. To compare, run curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh | sha256sum. The two should match.

After installation

Success looks like this: the installer prints StatePort is installed and healthy, a local address such as http://127.0.0.1:18216/ (your port may differ), and the path of an install receipt (a small file that records what was installed) below ~/.local/state/stateport-install.

  1. Open the printed http://127.0.0.1:…/ address in your Windows browser. The first screen opens empty: no applications installed, worker execution disabled, provider not configured. That is normal.
  2. Click Open the study sample (a small study-plan app). It installs the bundled sample, records a receipt and opens it after about ten seconds. The Applications list at the left may keep saying that no applications exist until you reload. The 72-second field guide shows what to look for.
  3. To try your own project, place a Git repository below /var/lib/stateport/imports and use Catalog → Import a repository. On Alpha.21 such a checkout was imported without an ownership fix (not repeated on Alpha.23). If it does not appear, see troubleshooting.

The study sample needs no provider login: everything in it is proposed by a fixed script. Chat replies and coding-agent runs would need a provider connection, and they have not been shown to work. Importing a template from a public Git URL was not tested.

Open the template workflow or read the full getting-started guide.

What happens when you close WSL windows

StatePort runs inside WSL. Windows normally stops WSL when the last window closes, so the installer adds a small Windows scheduled task named StatePortKeepAlive that keeps Ubuntu running in the background once you have signed in to Windows.

Be aware: on Alpha.23 the task is registered to start at Windows start-up, at sign-in and every 10 minutes, to run when nobody is signed in, and to run on battery power. On the test machine it had never run, so whether it keeps StatePort reachable was not measured. Windows may allow only a smaller version for your account (for example sign-in only); the installer says so at the end of the install. On Alpha.21 the task ran only at sign-in and was set not to start on battery power; it had never run on the test machine either. On Alpha.20, on a real Windows 11 host, it held the environment after a sign-in, and before that sign-in closing the last Ubuntu window stopped the product, which came back about three minutes after Ubuntu was reopened. Surviving a Windows reboot was not measured (reboot: not measured). If the local address stops answering, open an Ubuntu window and reload after a few minutes, or sign out of Windows and back in, then reload the page.

Stop or remove StatePort

  • Stop it for now: run wsl --shutdown in PowerShell. That stops every WSL distribution, StatePort included, and it can stay stopped until your next Windows sign-in.
  • Uninstall: the command above only installs. The Alpha.23 installer prints options to stop and remove StatePort (your data is kept) and to reinstall it. They passed in a Linux test lab that imitates WSL2; they were not run on Windows, and this page has no one-line uninstall. The update and removal guide says what is and is not known. Do not run an installer from another release against an Alpha.22 install.
  • Cleanest option: try StatePort in a throwaway WSL distribution or virtual machine and delete that when you are done. Deleting a distribution deletes everything inside it, so only do this with a test one.
  • Keep-alive task: if you remove StatePort, also delete the StatePortKeepAlive task in Windows Task Scheduler (or run schtasks /Delete /TN StatePortKeepAlive /F in PowerShell). This removal path is untested.

Something went wrong? Report a problem

Open an issue at github.com/lennertvhoy/StatePort-Site/issues (opens in a new tab). Please include:

  • the version (Alpha.23) and the last lines of the installer’s output; failures start with StatePort install:;
  • the output of ps -p 1 -o comm= in Ubuntu and of wsl --list --verbose in PowerShell;
  • which step it stopped at.

Remove passwords, tokens, private URLs, and personal file contents before you post.
