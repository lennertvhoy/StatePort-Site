Install StatePort Alpha.26

One command installs StatePort on Windows 11 with WSL2 and Ubuntu 24.04. It sets up a web interface, an API, a background worker, storage and a sandbox where work runs.

Alpha.26 installs on Windows 11 with WSL2 and Ubuntu 24.04. It is an early alpha with known limits, listed below.

StatePort is in early alpha. Do not use it for important data. Use test data and keep your own backups. Alpha.26 is meant for one person on one Windows 11 computer; it is not production software. There is no supported way back to an earlier release.

Exact status statement (for reviewers)

StatePort 0.1.0-alpha.26 is the current public alpha. Its signed release index marks it a qualification candidate; it is not yet qualified. The index also declares rollback unsupported. On 22 October 2026, in a fresh Windows 11 test virtual machine (a KVM guest on a Linux workstation, not bare metal) with WSL2 and stock Ubuntu 24.04, reset to a clean snapshot, the versioned one-line command for these exact signed bytes installed StatePort 0.1.0-alpha.26 and exited 0 in 466 seconds; a second run over the finished install reported that it was already installed and changed nothing. The bundled study sample ran end to end. ProjectState_Template, StudyState_Template and a third template were imported by their public addresses and their check actions ran; all three survived a restart of the StatePort services and a full WSL restart, after which the Windows keep-alive task started Ubuntu again on its own after 68 seconds. In Microsoft Edge inside the virtual machine the interface's applications, catalog, approvals, runs, receipts, backup, restore as a new application, rename and settings worked through their real effects. Uninstall with the documented stateport command kept the data, an identical reinstall brought it back, and purge removed it. With StatePort idle, WSL held about 1.2 GB of Windows memory and no swap was used; the install grew the WSL disk by about 3.8 GB. After a cold power cycle of the virtual machine the keep-alive task started Ubuntu, but StatePort did not answer afterwards: Windows reboot survival did not pass and is being investigated. Not measured on Alpha.26: agent actions and chat (OpenCode's anonymous free route had reached its usage limit from the test connection), the upgrade from Alpha.24, and resource use on office hardware.

Before you start

Work through these in order. Each one is a check you can run in a minute.

  1. Windows 11 on a 64-bit Intel or AMD computer, with an internet connection and several gigabytes of free disk space.
  2. WSL2 with Ubuntu 24.04. If you do not have it yet, open PowerShell and run the command below, restart if Windows asks, then open Ubuntu and create your Linux user. To confirm Ubuntu runs as WSL2, run wsl --list --verbose in PowerShell and look for 2 in the VERSION column. 
    wsl --install -d Ubuntu-24.04
  3. A normal Ubuntu user with sudo. Do not run the installer as root.
  4. systemd switched on inside Ubuntu. In Ubuntu, run the command below. It should print systemd. 
    ps -p 1 -o comm=
    If it prints anything else, open /etc/wsl.conf with sudo nano /etc/wsl.conf, keep any lines already there, and add these two lines (skip the first if a [boot] section already exists): 
    [boot]
systemd=true
    Then run wsl --shutdown in PowerShell and reopen Ubuntu. This stops every running WSL distribution, so save your work first.

Read the longer getting-started guide for the same checks in more detail.

Optional: run a dry run first

Add --transport-probe to the command. It installs nothing and does not ask for sudo: it checks your machine (WSL2, Ubuntu 24.04, systemd, Windows 11), downloads the list of container images with their fingerprints, and checks those fingerprints. If a prerequisite is missing, it stops and names it.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh) --transport-probe

A passing dry run ends with a line that says the transport probe passed and that the installer was not executed.

Install

Open Ubuntu 24.04 in WSL2 and run this as your normal Ubuntu user, in any folder including your home folder. The cd /tmp workaround that Alpha.24 needed is no longer needed.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

What the installer does and asks, in order:

  1. Checks your machine before changing anything, then downloads the release and checks each file against a fingerprint.
  2. Asks for your Ubuntu password (sudo) to install a few system packages.
  3. Shows the package plan and asks you to type install-packages to approve it.
  4. Shows the exact install plan and asks you to type install-exact to approve it.
  5. Installs and starts StatePort, then prints the result.

Expect it to take several minutes. On this release the install took 466 seconds (about 8 minutes) once, on a local Windows 11 test virtual machine; the previous release's public command took 474 seconds there. Allow more on a slow connection or a slower computer. If it stops with package_installation_invalid, wait a minute and run the same command again; troubleshooting explains why.

You can check the installer before you run it. Its SHA-256 fingerprint is a1cd19571745631b3537c9458f1338c8231984870556fc34e3c5973bf16ecc5a. To compare, run curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh | sha256sum. The two should match.

After installation

Success looks like this: the installer prints StatePort is installed and healthy, a local address such as http://127.0.0.1:18216/ (your port may differ), and the path of an install receipt (a small file that records what was installed) below ~/.local/state/stateport-install.

  1. Open the printed http://127.0.0.1:…/ address in your Windows browser. The first screen opens empty: no applications installed, worker execution disabled, provider not configured. That is normal.
  2. Click Open the study sample (a small study-plan app). It installs the bundled sample, records a receipt and opens it after about ten seconds. The Applications list at the left may keep saying that no applications exist until you reload. The 72-second field guide shows what to look for.
  3. To try your own project, place a Git repository below /var/lib/stateport/imports and use Catalog → Import a repository, or give a public repository address and, if you want one, a branch, tag or commit. If it does not appear, see troubleshooting.

The study sample needs no provider login. Chat and the agent actions need a model, and you can use OpenCode's free models without an account, after accepting their terms. Importing a template gives you that template's own check and its own actions.

What happens when you close WSL windows

StatePort runs inside WSL. Windows normally stops WSL when the last window closes, so the installer adds a small Windows scheduled task named StatePortKeepAlive that keeps Ubuntu running in the background once you have signed in to Windows.

Be aware: the Windows task that keeps Ubuntu running is registered to start at Windows start-up, at sign-in and every 10 minutes. After a full WSL shutdown on the test virtual machine, the task started Ubuntu again on its own after 68 seconds, and StatePort answered with its data intact. What happens after a Windows restart is not measured yet for this release. If the local address stops answering, open an Ubuntu window and reload after a few minutes, or sign out of Windows and back in, then reload the page.

Stop or remove StatePort

  • Stop it for now: run wsl --shutdown in PowerShell. That stops every WSL distribution, StatePort included, and it can stay stopped until your next Windows sign-in.
  • Remove it: ~/.local/state/stateport-install/bin/stateport uninstall removes StatePort and keeps your data; ~/.local/state/stateport-install/bin/stateport purge deletes the data as well, after you type a confirmation, and needs your sudo password. Measured: uninstall (the documented stateport uninstall) removed StatePort and kept your data; installing again brought the same applications back; purge (stateport purge, with its typed confirmation) removed the data and records. Purge keeps a copied OpenCode sign-in (see Security and privacy). The update and removal guide has the details. Do not run an installer from another release against a newer install.
  • Cleanest option: try StatePort in a throwaway WSL distribution or virtual machine and delete that when you are done. Deleting a distribution deletes everything inside it, so only do this with a test one.
  • Keep-alive task: if you remove StatePort, also delete the StatePortKeepAlive task in Windows Task Scheduler (or run schtasks /Delete /TN StatePortKeepAlive /F in PowerShell). This removal path is untested.

Something went wrong? Report a problem

Open an issue at github.com/lennertvhoy/StatePort-Site/issues (opens in a new tab). Please include:

  • the version (Alpha.26) and the last lines of the installer’s output; failures start with StatePort install:;
  • the output of ps -p 1 -o comm= in Ubuntu and of wsl --list --verbose in PowerShell;
  • which step it stopped at.

Remove passwords, tokens, private URLs, and personal file contents before you post.
