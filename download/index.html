Install StatePort Alpha.21

One command installs StatePort on Windows 11 with WSL2 and Ubuntu 24.04. It sets up a web interface, an API, a background worker, storage and a sandbox where work runs.

Alpha.21 came up healthy on 2 of 3 fresh Windows 11 test installs, in about 12 to 18 minutes. It is an early alpha with known limits, listed below.

StatePort is in early alpha. Do not use it for important data. Use test data and keep your own backups. Alpha.21 is meant for one person on one Windows 11 computer; it is not production software.

What has and has not been tested

  • Tested: the one-line command installed Alpha.21 and it came up healthy on 2 of 3 fresh test installs of Windows 11 with WSL2 and stock Ubuntu 24.04. Through the public route one attempt installed in about 12 minutes; another was refused after about 5 minutes with package_installation_invalid (see troubleshooting). An install from a local copy of the same signed files took about 18 minutes. All were virtual machines, not physical PCs.
  • Tested: the StudyState sample (a small study-plan app) in the browser on an installed Alpha.21: open it with one click, start an activity, review the exact change, approve, write a reflection, and open the receipt. The saved state was still there after a reload. Going back from a review withdraws the proposed change.
  • Tested: importing a ProjectState and a StudyState template from a local Git checkout, in the browser and through the API, without an ownership fix. Through the API: undo of the last evidence update, export and import, a verified backup and restore as a new instance (the request needs a destination name). The notifications list and the Back up now button also worked.
  • Not working yet: on Alpha.21, coding-agent runs are refused before they start, chat replies fail because no AI provider could be connected, restore from the interface fails, provider actions in the interface were refused, the workbench terminal and files tools do not work, and per-application workspaces are unavailable. The Learning tab can show old numbers until you reload, and refused changes give vague error messages. The keep-alive task had not run on the test machine and did not start after an unplanned restart. A planned Windows reboot is not measured, undo in the browser did not finish, and uninstall is not finished. The full list is on current limitations.
Exact status statement (for reviewers)

StatePort 0.1.0-alpha.21 is the current signed release. Its installation was measured on fresh Windows 11 test machines with WSL2 and stock Ubuntu 24.04: it came up healthy on 2 of 3 attempts, one through the public one-line route (about 12 minutes) and one from a local copy of the same signed files (about 18 minutes). The third attempt, through the public route, was refused after about 5 minutes by a package check that races Ubuntu's background updater, and the next attempt succeeded. On the installed product the study sample worked in the browser (start an activity, review, approve, reflect, receipt, saved state after a reload), and undo, export and import, backup and restore as a new instance worked through the API. The installed keep-alive task had not run on the test machine, and it did not start after an unplanned restart when nobody was signed in. Windows reboot survival and uninstall were not measured as planned tests. Coding-agent runs, chat replies, restore from the interface, the workbench terminal and files tools, per-application workspaces, and the standing-authority and updater pages did not work on Alpha.21.

Before you start

Work through these in order. Each one is a check you can run in a minute.

  1. Windows 11 on a 64-bit Intel or AMD computer, with an internet connection and several gigabytes of free disk space.
  2. WSL2 with Ubuntu 24.04. If you do not have it yet, open PowerShell and run the command below, restart if Windows asks, then open Ubuntu and create your Linux user. To confirm Ubuntu runs as WSL2, run wsl --list --verbose in PowerShell and look for 2 in the VERSION column. 
    wsl --install -d Ubuntu-24.04
  3. A normal Ubuntu user with sudo. Do not run the installer as root.
  4. systemd switched on inside Ubuntu. In Ubuntu, run the command below. It should print systemd. 
    ps -p 1 -o comm=
    If it prints anything else, open /etc/wsl.conf with sudo nano /etc/wsl.conf, keep any lines already there, and add these two lines (skip the first if a [boot] section already exists): 
    [boot]
systemd=true
    Then run wsl --shutdown in PowerShell and reopen Ubuntu. This stops every running WSL distribution, so save your work first.

Read the longer getting-started guide for the same checks in more detail.

Optional: run a dry run first

Add --transport-probe to the command. It installs nothing and does not ask for sudo: it checks your machine (WSL2, Ubuntu 24.04, systemd, Windows 11), downloads the list of container images with their fingerprints, and checks those fingerprints. If a prerequisite is missing, it stops and names it.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh) --transport-probe

A passing dry run ends with a line that starts StatePort Alpha.21 transport probe passed.

Install

Open Ubuntu 24.04 in WSL2 and run this as your normal Ubuntu user:

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

What the installer does and asks, in order:

  1. Checks your machine before changing anything, then downloads the release and checks each file against a fingerprint.
  2. Asks for your Ubuntu password (sudo) to install a few system packages.
  3. Shows the package plan and asks you to type install-packages to approve it.
  4. Shows the exact install plan and asks you to type install-exact to approve it.
  5. Installs and starts StatePort, then prints the result.

Expect it to take a while: about 12 to 18 minutes on a test virtual machine, and longer on a slow connection. If it stops with package_installation_invalid, wait a minute and run the same command again; troubleshooting explains why.

You can check the installer before you run it. Its SHA-256 fingerprint is 5fc574f25072f1c801cd40a098126eb230934e8af4f18f8e5c1518955d0cc9e0. To compare, run curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh | sha256sum. The two should match.

After installation

Success looks like this: the installer prints StatePort is installed and healthy, a local address such as http://127.0.0.1:18216/ (your port may differ), and the path of an install receipt (a small file that records what was installed) below ~/.local/state/stateport-install.

  1. Open the printed http://127.0.0.1:…/ address in your Windows browser. The first screen opens empty: no applications installed, worker execution disabled, provider not configured. That is normal.
  2. Click Open the study sample (a small study-plan app). It installs the bundled sample, records a receipt and opens it after about ten seconds. The Applications list at the left may keep saying that no applications exist until you reload. The 72-second field guide shows what to look for.
  3. To try your own project, place a Git repository below /var/lib/stateport/imports and use Catalog → Import a repository. On Alpha.21 such a checkout was imported without an ownership fix. If it does not appear, see troubleshooting.

The study sample needs no provider login: everything in it is proposed by a fixed script. Chat replies and coding-agent runs would need a provider connection, and they have not been shown to work. Importing a template from a public Git URL was not tested.

What happens when you close WSL windows

StatePort runs inside WSL. Windows normally stops WSL when the last window closes, so the installer adds a small Windows scheduled task named StatePortKeepAlive that keeps Ubuntu running in the background once you have signed in to Windows.

Be aware: on Alpha.21 the task was registered and enabled, but it had never run on the test machine, because it only starts at a Windows sign-in and no sign-in happened after it was registered. Whether it keeps StatePort reachable was not measured on Alpha.21. On Alpha.20, on a real Windows 11 host, it held the environment after a sign-in, and before that sign-in closing the last Ubuntu window stopped the product, which came back about three minutes after Ubuntu was reopened. The task is also set not to start on battery power, so on a laptop running on battery it may not keep WSL running. Surviving a Windows reboot was not measured. If the local address stops answering, open an Ubuntu window and reload after a few minutes, or sign out of Windows and back in (that is when the keep-alive task starts), then reload the page.

Stop or remove StatePort

  • Stop it for now: run wsl --shutdown in PowerShell. That stops every WSL distribution, StatePort included, and it can stay stopped until your next Windows sign-in.
  • Uninstall: the command above only installs. Uninstalling and reinstalling Alpha.21 have not been tested, and this page has no one-line uninstall. The update and removal guide says what is and is not known. Do not run an installer from another release against an Alpha.21 install.
  • Cleanest option: try StatePort in a throwaway WSL distribution or virtual machine and delete that when you are done. Deleting a distribution deletes everything inside it, so only do this with a test one.
  • Keep-alive task: if you remove StatePort, also delete the StatePortKeepAlive task in Windows Task Scheduler (or run schtasks /Delete /TN StatePortKeepAlive /F in PowerShell). This removal path is untested.

Something went wrong? Report a problem

Open an issue at github.com/lennertvhoy/StatePort-Site/issues (opens in a new tab). Please include:

  • the version (Alpha.21) and the last lines of the installer’s output; failures start with StatePort install:;
  • the output of ps -p 1 -o comm= in Ubuntu and of wsl --list --verbose in PowerShell;
  • which step it stopped at.

Remove passwords, tokens, private URLs, and personal file contents before you post.
