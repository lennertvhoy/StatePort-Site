Install StatePort Alpha.20

One command installs StatePort on Windows 11 with WSL2 and Ubuntu 24.04. It sets up a web interface, an API, a background worker, storage and a sandbox where work runs.

Alpha.20 installed successfully, and came up healthy, five times on fresh Windows 11 virtual machines. It is an early alpha with known limits, listed below.

StatePort is in early alpha. Do not use it for important data. Use test data and keep your own backups. Alpha.20 is meant for one person on one Windows 11 computer; it is not production software.

What has and has not been tested

  • Tested: the one-line command below installed Alpha.20 successfully, and it came up healthy, five times on fresh Windows 11 virtual machines with WSL2 and stock Ubuntu 24.04 (two earlier runs and three on 30 September 2026). All five were virtual machines, not physical PCs.
  • Tested: after an interactive Windows sign-in, a small keep-alive task keeps StatePort reachable after the last WSL window is closed.
  • Not tested yet: whether StatePort survives a Windows reboot, working with templates on Windows, uninstalling and reinstalling, a screen-by-screen check of the whole interface, and speed and resource use. The StudyState Sample loop (review, approve, reflect, receipt) is implemented and passes in the project’s automated tests, but has not yet been run end to end on an installed Alpha.20.
Exact status statement (for reviewers)

StatePort 0.1.0-alpha.20 is the current signed candidate; its installed-product rehearsal passed in an isolated simulation environment, and its public-route installation completed and came up healthy on a genuine Windows 11 host with WSL2 and stock Ubuntu 24.04. After an interactive Windows logon the installed keep-alive task held the WSL environment, and the installed product stayed reachable after the last WSL session closed on that host. Windows reboot survival and the remaining lifecycle, template, UI and efficiency checks are in progress.

Before you start

Work through these in order. Each one is a check you can run in a minute.

  1. Windows 11 on a 64-bit Intel or AMD computer, with an internet connection and several gigabytes of free disk space.
  2. WSL2 with Ubuntu 24.04. If you do not have it yet, open PowerShell and run the command below, restart if Windows asks, then open Ubuntu and create your Linux user. To confirm Ubuntu runs as WSL2, run wsl --list --verbose in PowerShell and look for 2 in the VERSION column. 
    wsl --install -d Ubuntu-24.04
  3. A normal Ubuntu user with sudo. Do not run the installer as root.
  4. systemd switched on inside Ubuntu. In Ubuntu, run the command below. It should print systemd. 
    ps -p 1 -o comm=
    If it prints anything else, open /etc/wsl.conf with sudo nano /etc/wsl.conf, keep any lines already there, and add these two lines (skip the first if a [boot] section already exists): 
    [boot]
systemd=true
    Then run wsl --shutdown in PowerShell and reopen Ubuntu. This stops every running WSL distribution, so save your work first.

Read the longer getting-started guide for the same checks in more detail.

Optional: run a dry run first

Add --transport-probe to the command. It installs nothing and does not ask for sudo: it checks your machine (WSL2, Ubuntu 24.04, systemd, Windows 11), downloads the list of container images with their fingerprints, and checks those fingerprints. If a prerequisite is missing, it stops and names it.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh) --transport-probe

A passing dry run ends with a line that starts StatePort Alpha.20 transport probe passed.

Install

Open Ubuntu 24.04 in WSL2 and run this as your normal Ubuntu user:

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

What the installer does and asks, in order:

  1. Checks your machine before changing anything, then downloads the release and checks each file against a fingerprint.
  2. Asks for your Ubuntu password (sudo) to install a few system packages.
  3. Shows the package plan and asks you to type install-packages to approve it.
  4. Shows the exact install plan and asks you to type install-exact to approve it.
  5. Installs and starts StatePort, then prints the result.

Expect it to take a while: about 20 minutes on my test virtual machine, and longer on a slow connection.

You can check the installer before you run it. Its SHA-256 fingerprint is b83e8376776cd663b6a0aa8098ddde489f0125e033d70e8b1421fb04d1cb8916. To compare, run curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh | sha256sum. The two should match.

After installation

Success looks like this: the installer prints StatePort is installed and healthy, a local address such as http://127.0.0.1:18012/ (your port may differ), and the path of an install receipt (a small file that records what was installed) below ~/.local/state/stateport-install.

  1. Open the printed http://127.0.0.1:…/ address in your Windows browser.
  2. Install the StudyState sample (a small study-plan app) from Catalog. The 72-second field guide shows what to look for.
  3. To try your own project, place a Git repository below /var/lib/stateport/imports and use Catalog → Import a local repository.

I have not tested templates on Windows yet, and that includes the StudyState sample, so expect rough edges. The sample’s review, approve, reflect and receipt steps pass the project’s automated tests. I have not yet run them on an installed Alpha.20.

Open the template workflow or read the full getting-started guide.

What happens when you close WSL windows

StatePort runs inside WSL. Windows normally stops WSL when the last window closes, so the installer adds a small Windows scheduled task named StatePortKeepAlive that keeps Ubuntu running in the background once you have signed in to Windows. On the test virtual machines, StatePort stayed reachable after the last WSL window was closed.

Be aware: this was checked on virtual machines after an interactive Windows sign-in. Closing all WSL windows, running wsl --shutdown, or restarting Windows can still leave StatePort stopped until your next Windows sign-in. Surviving a Windows reboot has not been measured. If the local address stops answering, try signing out of Windows and back in (that is when the keep-alive task starts), then reload the page.

Stop or remove StatePort

  • Stop it for now: run wsl --shutdown in PowerShell. That stops every WSL distribution, StatePort included, and it can stay stopped until your next Windows sign-in.
  • Uninstall: the command above only installs. Uninstalling and reinstalling Alpha.20 have not been tested, and this page has no one-line uninstall. The update and removal guide says what is and is not known. Do not run an installer from another release against an Alpha.20 install.
  • Cleanest option: try StatePort in a throwaway WSL distribution or virtual machine and delete that when you are done. Deleting a distribution deletes everything inside it, so only do this with a test one.
  • Keep-alive task: if you remove StatePort, also delete the StatePortKeepAlive task in Windows Task Scheduler (or run schtasks /Delete /TN StatePortKeepAlive /F in PowerShell). This removal path is untested.

Something went wrong? Report a problem

Open an issue at github.com/lennertvhoy/StatePort-Site/issues (opens in a new tab). Please include:

  • the version (Alpha.20) and the last lines of the installer’s output; failures start with StatePort install:;
  • the output of ps -p 1 -o comm= in Ubuntu and of wsl --list --verbose in PowerShell;
  • which step it stopped at.

Remove passwords, tokens, private URLs, and personal file contents before you post.
