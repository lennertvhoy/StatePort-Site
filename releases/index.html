Current software status

Alpha.26 is the current early alpha

Release label. Alpha.26 is the current public alpha, and it is an early alpha. There is no supported way back to an earlier release: you can move forward to a newer one, and data saved by one release may not be usable in another.

Alpha.26 is installed on Windows 11 with WSL2 and Ubuntu 24.04 from one command. It gives you a web interface, an API, storage and a sandbox on your own machine, and an address that only your computer can reach. It needs no account for anything except the agent actions and the chat, and for those you can use OpenCode's free models after accepting their terms. The measurements for this release are not in yet. The install, the study sample, a service restart, a full WSL restart and an import from GitHub were measured on the previous release in a Windows 11 test virtual machine, which is a virtual machine and not a physical computer.

Not working yet. You cannot go back to an older release. The three templates have not been imported and measured in this release yet. Chat answers questions, reading the files that the template's actions say a model may read, and never changes anything. One undo exists, for the last evidence update in the study sample. A backup holds the files of one application, not its history or its conversations. There is no team, no hosted version and no supported way to reach it over a network. The measurements above are not in yet. The full list is on current limitations.

Before you use StatePort

StatePort is in early alpha. Do not use it for important data.

It is built by one person, in the open. The measurement notes for the Alpha.20 runs are in the public repository under evidence/alpha20-public-install-001 (opens in a new tab), and technical release files remain available for developers and anyone who wants to check them.

Exact status statement (for reviewers)

StatePort 0.1.0-alpha.24 is the current public alpha. Its signed release index marks it a qualification candidate; it is not yet qualified. The index also declares rollback unsupported. It installs and passes in a clean test VM; real-Windows and reboot results pending (reboot: not measured). In a fresh Windows 11 test virtual machine (a KVM guest on a Linux workstation, not bare metal) with WSL2 and stock Ubuntu 24.04, reset to a clean snapshot, the public one-line command installed StatePort 0.1.0-alpha.24 and exited 0 in 474 seconds (one attempt on the public bytes); an earlier install of the same signed files from a local copy also exited 0. All services reported healthy, the web page and the API answered, and a second run of the installer over a finished install reported that it was already installed and changed nothing. The bundled study sample ran end to end: start an activity, review the exact proposed change, approve it, open the receipt, write a reflection, with the durable result read back through the product's own interface; the saved data was still there after restarting the StatePort services and after a full WSL distribution restart (7 of 7 checks both times). Importing the StudyState template from GitHub inside StatePort worked: the repository was inspected, planned and installed as a new instance. The API port named in the install manifest (18097) was the port the started API answered on, and the manifest ports of the web service and the worker matched their published ports too. Restarting the StatePort target with systemctl --user restart stateport-accepted.target restarted all three containers. The web service now has outbound internet access, through a second network of its own (the web container resolved github.com), which GitHub import needs and AI provider connections will need; the API and worker stay isolated on the internal network and could not resolve external names, by design. Not measured on Alpha.24: the installer's handling of a slow Windows keep-alive registration (the slow case did not occur in these runs), a Windows reboot, uninstall and reinstall on Windows, importing ProjectState or a third template, a screen-by-screen interface audit, and resource use on office hardware. On the previous release, Alpha.23, the public command exited 0 on 3 of 4 attempts (the 4th crashed in the optional Windows keep-alive registration on a 120-second PowerShell timeout), the install plan named API port 18464 while the started API answered on 18447, and importing the StudyState template from GitHub failed because the containers could not resolve external host names. The optional keep-alive task is registered to start at Windows start-up, at sign-in and every 10 minutes, but it had not run on the test machine. Reboot: not measured. Uninstall was not run on Windows. A browser click-through of the study sample was last measured on Alpha.21. On Alpha.21, coding-agent runs, chat replies, restore from the interface, the workbench terminal and files tools, per-application workspaces, and the standing-authority and updater pages did not work, and none of that has been measured on an installed Alpha.24.
