Current software status

Alpha.23 is the current early alpha

Alpha.23 is installed on Windows 11 with WSL2 and Ubuntu 24.04 from one command. It installs and passes in a clean test VM; real-Windows and reboot results are pending. In that test, on a pristine Windows 11 virtual machine (a KVM guest on a Linux workstation, not bare metal), the public one-line command exited 0 in about 9 minutes (3 of 4 attempts on these bytes; the 4th crashed in the optional Windows keep-alive registration on a 120-second PowerShell timeout, not repeated; a fix is prepared but not released), all services reported healthy, the web page and the API answered, and a second run of the installer changed nothing. The web interface opens without a login. The browser walk-through of the study sample (open it with one click, start an activity, review the exact change, approve it, write a reflection, open the receipt, find the saved state after a reload) was last measured on Alpha.21 and has not been repeated on Alpha.23.

Not working yet: on Alpha.21, coding-agent runs were refused before they started, chat replies failed because no AI provider could be connected, restore from the interface failed, provider actions in the interface were refused, the workbench terminal and files tools did not work, per-application workspaces were unavailable, the standing-authority and updater pages showed errors, and the background worker ran no jobs. None of this has been measured again on an installed Alpha.23. The keep-alive task is registered but had not run on the test machine. A Windows reboot is not measured (reboot: not measured), undo in the browser has not been tried on Alpha.23, and uninstall was not run on Windows. The full list is on current limitations.

Before you use StatePort

StatePort is in early alpha. Do not use it for important data.

It is built by one person, in the open. The measurement notes for the Alpha.20 runs are in the public repository under evidence/alpha20-public-install-001 (opens in a new tab), and technical release files remain available for developers and anyone who wants to check them.

Exact status statement (for reviewers)

StatePort 0.1.0-alpha.23 is the current signed release. It installs and passes in a clean test VM; real-Windows and reboot results pending (reboot: not measured). In a fresh Windows 11 test virtual machine (a KVM guest on a Linux workstation, not bare metal) with WSL2 and stock Ubuntu 24.04, the public one-line command installed StatePort and exited 0 in about 9 minutes on a pristine machine; that was 3 of 4 attempts on these bytes, and the 4th crashed in the optional Windows keep-alive registration on a 120-second PowerShell timeout (not repeated; a fix is prepared but not released). All services reported healthy, the web page and the API answered, and on the same bytes a second run of the installer over a finished install reported that it was already installed and changed nothing. The bundled study sample ran end to end: start an activity, review the exact proposed change, approve it, open the receipt, write a reflection, with the durable result read back through the product's own interface; the saved data was still there after restarting the StatePort services and after a full WSL distribution restart (7 of 7 checks both times). One measured defect stays open: the install plan and manifest named API port 18464 while the started API actually answered on port 18447; the installer prints the address of the service that is really listening, so the printed web address worked. Importing the StudyState template from GitHub inside StatePort fails on a stock WSL2 install: the product's containers cannot resolve external host names (measured), so anything that needs the internet from inside StatePort does not work yet. The optional keep-alive task is registered to start at Windows start-up, at sign-in and every 10 minutes, but it had not run on the test machine. Reboot: not measured. Uninstall was not run on Windows. A browser click-through of the study sample was last measured on Alpha.21. On Alpha.21, coding-agent runs, chat replies, restore from the interface, the workbench terminal and files tools, per-application workspaces, and the standing-authority and updater pages did not work, and none of that has been measured on an installed Alpha.23.
