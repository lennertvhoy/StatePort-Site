Design exercise. The example below is small on purpose. You will not install anything.

The situation

Imagine that an application wants to move one study session from Wednesday to Thursday. A useful record should answer more than "did the assistant say it was done?"

Read the stages in order

request: move session / Wed → Thu approval: approved by the user change: applied checks: schedule rules passed record: saved

The record should describe the same request you reviewed. If the request changes, the application should ask again. It should also show when approved work failed before making a change.

Ask five questions

  1. Which application does this concern?
  2. What did it ask to change?
  3. Who approved the request?
  4. What changed, and did the checks pass?
  5. What still needs attention?

Know what the record cannot tell you

A change record cannot tell you whether moving the session was a good idea or whether the learner understood the choice. It also cannot promise that another service can undo a change. Those questions still need your judgement.
