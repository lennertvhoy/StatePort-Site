Why it matters

Three things stay true.

01

Your work stays yours

Goals, decisions, and history live in readable files on your own machine — not in a session locked inside someone else's chat.

02

Continuity is designed for restarts

The design keeps goals, decisions, and history in durable files so work can resume after a restart; provider portability remains a proposed boundary, not a signed release capability claim.

03

Change stays reviewable

Proposals, approvals, applied results, and receipts remain separate facts — so important change can be checked, traced, and undone.

How it works

Template, governed run, kept result.

01 / TEMPLATE

Start from a template

Each application is a bundle of durable state files plus the scripts an agent is allowed to run — a home the work can live in.

02 / RUN

Let it run, governed

The proposed governed flow plans work, runs an agent, asks approval when it matters, and records what changed. Watching, pausing, redirecting, and rolling back are design language, not a claim of current signed-release availability.

03 / KEEP

Keep the result

The design keeps decisions, files, and history in an instance. Provider or model changes are a proposed portability boundary, not a current signed-release capability claim.
