The idea

The application is the durable thing.

A coding agent can perform work. It should not own the goal, permissions, state, evidence, or acceptance. StatePort owns that boundary; the execution harness owns how an authorized run is carried out.

Chat remains useful inside the application, but neither a transcript nor a provider session silently becomes its canonical state.

Why it matters

Three things should remain true.

01

Purpose and state outlive a session

Each instance has a pinned definition, user-controlled state, declared authority, and history that can be inspected without replaying a chat.

02

Authority and evidence stay explicit

Intent, permission, candidate output, validation, application, and human acceptance remain separate facts.

03

Execution is capability-bound

The current private-alpha path is Codex in supervised-direct mode. A future provider change must declare its different behavior and limitations; continuity does not imply equivalence.

How it works

From purpose to accepted change.

01 / OPEN

Start from the application

See the objective, durable state, recent change, and anything that needs attention before asking an agent to act.

02 / PREPARE

Bind intent and authority

StatePort prepares an exact action against an exact instance revision, with the effective capabilities and approval policy visible.

03 / EXECUTE

Supervise bounded execution

The harness runs the current provider inside its declared boundary. StatePort captures observations and keeps candidate output noncanonical.

04 / ACCEPT

Validate before acceptance

A finished run, a produced candidate, a passed validator, an applied change, and human acceptance remain distinguishable.
