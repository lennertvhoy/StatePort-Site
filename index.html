The study example

The study sample, step by step

The sample app is a small study planner called StudyState. It keeps a goal and a few activities. You start an activity and approve the change it proposes. Then you write a reflection and approve saving it. The goal, activities and reflection are saved as files on your computer.

These screens show the sample. A receipt records the change you approved. The reflection is your own account of what you learned. Click a screen to enlarge it, or watch the 72-second walkthrough.

Try it

Install it with one command.

StatePort Alpha.24 is an early alpha. If you have a Windows 11 computer with WSL2 and Ubuntu 24.04, you can install it with one command. Use a test machine and test data only.

01 / CHECK

Check the machine

Windows 11 on a 64-bit Intel or AMD PC, WSL2 with Ubuntu 24.04, systemd switched on, and a normal Ubuntu user that can use sudo. The download page lists each check.

02 / RUN

Run one command

Open Ubuntu and paste this as your normal user. Along the way it asks for your sudo password and for two typed confirmations.

bash <(curl -fsSL https://lennertvhoy.github.io/StatePort-Site/download/install.sh)

Want a dry run first? Add --transport-probe at the end. It installs nothing.

03 / OPEN

Open the local address

A successful run prints StatePort is installed and healthy and a local address such as http://127.0.0.1:18216/. Open it in your Windows browser.

Overview

What StatePort does

01

Your work is in files you own

Goals, decisions and history are saved as readable files on your own computer, not inside a chat session.

02

A new session starts from the saved files

State is saved on disk, not held in a chat window. On Alpha.21 the study sample's saved state was still there after a page reload; that was measured again on Alpha.23 and Alpha.24 through the product's own interface, with the saved data still there after a StatePort service restart and a full WSL distribution restart. Whether StatePort keeps running after the last Ubuntu window closes was not measured on Alpha.23 or Alpha.24, and a Windows reboot is not measured (reboot: not measured).

03

Changes wait for your approval

In the StudyState sample, a change is proposed first and you approve it. You can then open its receipt. Output from coding agents is recorded as a run result. StatePort does not yet save it into your app's state.

Current availability

Alpha.24 is the current release, and it is an early alpha

StatePort is in early alpha. Do not use it for important data. Here is exactly what works today, what is not working yet, and what is designed but not yet built.

What works today. Alpha.24 installs and passes in a clean test VM (Windows 11 with WSL2 and Ubuntu 24.04, in a virtual machine); real-Windows and reboot results are pending. In that test, from a local copy of the signed files, all services reported healthy, the web page and the API answered, and running the installer again changed nothing. It installs a web interface, an API, a background worker, storage and a sandbox on your own machine. On Alpha.24 the public one-line command finished in 474 seconds (one attempt), the bundled study sample ran end to end through the product's own interface, with the durable result read back, the saved data was still there after restarting the StatePort services and after a full WSL distribution restart, and importing the StudyState template from GitHub worked. On Alpha.23 the public command succeeded on 3 of 4 attempts and the GitHub import failed. The browser walk-through was last measured on Alpha.21: open the study sample with one click, start an activity, review and approve the exact change, write a reflection, open the receipt and find the saved state again after a reload; import a template from a local Git folder; and, through the API, undo the last evidence update, export and import, and back up and restore as a new instance.

Not working yet. On Alpha.21, coding-agent runs were refused before they started, chat replies failed because no AI provider could be connected, restoring from the interface failed, the provider actions in the interface were refused, the workbench terminal and files tools did not work, per-application workspaces were unavailable, the standing-authority and updater pages showed errors, and the background worker ran no jobs. The Learning tab could show old numbers until you reloaded, and refused changes gave vague error messages. Importing a StudyState repository does not add the study planner (the planner is the built-in sample). None of the Alpha.21 failures below has been measured again on an installed Alpha.24, so treat them as still not working. The keep-alive task is registered but had not run on the test machine, so whether StatePort stays reachable after the last Ubuntu window closes or after a restart is not measured (reboot: not measured). Uninstall was not run on Windows. Full list of limitations.

Planned. Undo for most changes, platform rollback, a chat assistant that reads your state, saving coding-agent output into your app's state, backups that include history and receipts, container deployment and Agent Kits.

Technical status of this release

StatePort 0.1.0-alpha.24 is the current signed release. It installs and passes in a clean test VM; real-Windows and reboot results pending (reboot: not measured). In a fresh Windows 11 test virtual machine (a KVM guest on a Linux workstation, not bare metal) with WSL2 and stock Ubuntu 24.04, reset to a clean snapshot, the public one-line command installed StatePort 0.1.0-alpha.24 and exited 0 in 474 seconds (one attempt on the public bytes); an earlier install of the same signed files from a local copy also exited 0. All services reported healthy, the web page and the API answered, and a second run of the installer over a finished install reported that it was already installed and changed nothing. The bundled study sample ran end to end: start an activity, review the exact proposed change, approve it, open the receipt, write a reflection, with the durable result read back through the product's own interface; the saved data was still there after restarting the StatePort services and after a full WSL distribution restart (7 of 7 checks both times). Importing the StudyState template from GitHub inside StatePort worked: the repository was inspected, planned and installed as a new instance. The API port named in the install manifest (18097) was the port the started API answered on, and the manifest ports of the web service and the worker matched their published ports too. Restarting the StatePort target with systemctl --user restart stateport-accepted.target restarted all three containers. The web service now has outbound internet access, through a second network of its own (the web container resolved github.com), which GitHub import needs and AI provider connections will need; the API and worker stay isolated on the internal network and could not resolve external names, by design. Not measured on Alpha.24: the installer's handling of a slow Windows keep-alive registration (the slow case did not occur in these runs), a Windows reboot, uninstall and reinstall on Windows, importing ProjectState or a third template, a screen-by-screen interface audit, and resource use on office hardware. On the previous release, Alpha.23, the public command exited 0 on 3 of 4 attempts (the 4th crashed in the optional Windows keep-alive registration on a 120-second PowerShell timeout), the install plan named API port 18464 while the started API answered on 18447, and importing the StudyState template from GitHub failed because the containers could not resolve external host names. The optional keep-alive task is registered to start at Windows start-up, at sign-in and every 10 minutes, but it had not run on the test machine. Reboot: not measured. Uninstall was not run on Windows. A browser click-through of the study sample was last measured on Alpha.21. On Alpha.21, coding-agent runs, chat replies, restore from the interface, the workbench terminal and files tools, per-application workspaces, and the standing-authority and updater pages did not work, and none of that has been measured on an installed Alpha.24.
